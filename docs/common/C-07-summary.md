## 一、階段性總結（Stage Summary）

### 1.1 觸發詞

使用者說「階段性總結」。

### 1.2 強制動作

| 步驟 | 動作 |
|---|---|
| 1 | 讀 P-02-progress 找上次總結標記 |
| 2 | 讀 C-05 分檔取新教訓 |
| 3 | 讀 C-06 更新 Token 記錄 |
| 4 | 回顧本次對話 |
| 5 | 更新 5 檔（C-05 分檔 / C-06 / P-02 / P-10 / P-03） |
| 6 | 標記「本次階段性總結 @ B{批次}」 |
| 7 | 生成進化報告供確認 |

### 1.3 觸發訊號（依可靠度排序）

| 優先 | 訊號 |
|---|---|
| 1 | AI 開始失誤（忘記路徑、重複問、未查 docs） |
| 2 | 客觀工作量（上傳 + 交付 ≥ 10 檔，或對話 ≥ 30 輪） |
| 3 | 任務切換 ≥ 3 個 |
| 4 | Token 剩餘偏低（僅參考） |

## 二、對照組強制（最高優先）

**原則**：遇到「單一帳號、單一裝置、單一頁面」異常時，**必須先建立對照組**。

| 異常類型 | 對照組做法 |
|---|---|
| 單一帳號異常 | 用全新帳號（或無痕 + 新帳號）登入 |
| 單一裝置異常 | 換另一台裝置 |
| 單一頁面異常 | 訪問其他同類頁面 |

**判斷**：

| 對照組結果 | 結論 |
|---|---|
| 正常 | 100% 是原狀態快取卡死 |
| 也異常 | 系統級問題，繼續排查 |

---

## 三、路徑問題強制前置

任何涉及「檔案路徑 / 資料夾結構」的建議，**必須先查 docs**。

| 步驟 | 動作 |
|---|---|
| 1 | grep P-01 §十 + P-03 |
| 2 | 若未記載 → 先補 docs，再回答 |
| 3 | 若與實際不符 → 先提醒，再修正 |
| 4 | 禁止憑印象回答路徑 |

**新增（D-133）**：提到 repo 時，一律用實際名稱（見 R-01 §三之一）；禁止「Repo A / Repo B」代稱。

## 四、輕量審視（新對話用）

| 觸發 | 動作 |
|---|---|
| 新對話要改的檔案，是上一輪交付過的 | 必須先審視上一輪交付 |
| 新對話是全新獨立任務 | 不需審視 |
| 階段性總結 | 一律審視 |

**目的**：兼顧安全與效率，避免每輪都背沉重歷史。

## 六、上傳共享包啟動流程（D-136 修正）

**核心**：使用者**上傳對應編號的共享包**給 AI。

| 對話類型 | 上傳 |
|---|---|
| 體系層 | 01-CORE-SYSTEM.md |
| 專案層 | 02-CORE-PROJECT.md + 90-{專案}.md |

**AI 讀到後**：

| 步驟 | 動作 |
|---|---|
| 1 | 回報共享包「構建編號」與「生成時間」 |
| 2 | 問使用者「是否為最新」 |
| 3 | 提示下一議題 |
| 4 | 列 4 選項（新專案 / 舊專案 / 純討論 / 其他） |
| 5 | 依情境處理 |

**若需其他分檔**：AI 依 C-02 §19.9 **主動提示上傳**（不得沉默不索取）。

## 七、新專案領域詢問流程（D-137）

**觸發**：使用者選「新專案」時。

| 步驟 | 動作 |
|---|---|
| 1 | **AI 先問領域** |
| 2 | 使用者回答（Web App / VBA / 資料分析 / …） |
| 3a | 已有領域 → 直接開新專案 |
| 3b | 新領域 → AI 主動建議建 `{X}-*` 6 檔 |
| 4 | 使用者確認 → 產出 6 檔草稿 |
| 5 | 依使用者回饋迭代 |
| 6 | **產出該專案 `notify.yml`** |

**6 檔模板**：見 C-00 §十一。
