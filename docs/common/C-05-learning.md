## 二、教訓（依時間倒序）

### [L-022] 未確認專案就自報對話編號

| 項目 | 內容 |
|---|---|
| 場景 | 新對話 004 在確認專案前，自報 `ai-system-20261016-004` |
| 錯誤 | 未確認專案就生成編號，沿用體系層慣用 code（ai-system） |
| 正確 | 先等使用者選專案，再依 PROJECT-LIST.md 的 code 生成；若已自報則作廢 |
| 適用規則 | C-00 §3.4（D-138） |

### [L-021] Token 估算反覆過度保守

| 項目 | 內容 |
|---|---|
| 場景 | 對話 A20261013-004，全程多次報「剩 8~16%」 |
| 錯誤 | 未依 D-102 重估，過度保守誤判；實際剩 30~40% |
| 正確 | 若估算 < 20% → 強制重估（採不同方法）；以平台顯示為準 |
| 適用規則 | C-02 §零點五（D-102） |

### [L-020] 重寫修改檔時漏掉 import

| 項目 | 內容 |
|---|---|
| 場景 | 重寫 entity-helpers.js 時憑記憶重寫（#081 / #089） |
| 錯誤 | 漏掉 `getMembersOnce` / `getBanksOnce` → members / banks 下拉清單空 |
| 正確 | 交付前先讀原檔，逐一核對所有 import |
| 適用規則 | C-02 §四之一 |

### [L-019] 交付修改檔未先看當前版本

| 項目 | 內容 |
|---|---|
| 場景 | 交 `ui/modal.js` 修改版（#092） |
| 錯誤 | 未先讀當前 modal.js（v103.0.23），刪除了原有堆疊 / bindModals / destroyModal |
| 正確 | 交付前必須先讀當前版本，只做最小改動 |
| 適用規則 | C-02 §四之一 |

### [L-018] 交付修改檔未標明 base version

| 項目 | 內容 |
|---|---|
| 場景 | 交 `sw.js` 修改版（#097） |
| 錯誤 | 只說「修改」，未標示基於哪個版本 |
| 正確 | 交付時標明「基於 #NNN 的 vX.Y.Z」 |
| 適用規則 | C-04 §一點五（D-101） |

### [L-017] 議題編號與回覆選項混淆

| 項目 | 內容 |
|---|---|
| 場景 | 使用者說「討論第 6 項」，AI 誤以為議題 6 |
| 錯誤 | 未確認使用者指「議題 6」還是「回覆選項 6」 |
| 正確 | 議題用數字、選項用字母；提問必附選項 |
| 適用規則 | C-02 §二之一、§9.4 |

### [L-016] Token 顯示格式與位置不一致

| 項目 | 內容 |
|---|---|
| 場景 | 不同對話 Token 顯示格式與位置不同 |
| 錯誤 | 舊對話用進度條 + 位置不一致 |
| 正確 | 固定格式「Token: {emoji} 剩餘: {pct}%」，位置一律回覆末尾 |
| 適用規則 | C-02 §零點五 |

### [L-015] md 檔案內誤用三反引號

| 項目 | 內容 |
|---|---|
| 場景 | 交付 .md 檔案，內含格式範例 |
| 錯誤 | 用三反引號包裹，渲染成灰框干擾 |
| 正確 | md 內零三反引號；範例用引用塊 |
| 適用規則 | C-02 §六點五 |

### [L-014] Spck Editor 手動上傳檔案失誤

| 項目 | 內容 |
|---|---|
| 場景 | 使用 Spck Editor 手動修改並推送 GitHub |
| 錯誤 | 把 A 檔案的代碼貼到 B 檔案 |
| 正確 | 每次推送前，逐一核對「檔名 ↔ 內容」 |
| 適用規則 | C-02 §十七 |
