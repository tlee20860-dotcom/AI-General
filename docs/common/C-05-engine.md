## 一、Token 管理（C-06 無損合併）

### 1.1 用途與目標

| 項目 | 說明 |
|---|---|
| 問題 | AI 對 Token 剩餘量的估算不準確 |
| 解法 | 以公式計算為主，累積數據校正 |
| 目標 | 累積數據後校正估算，使誤差 < 20% |

### 1.2 顯示規則

| Emoji | 剩餘 | 行為 |
|---|---|---|
| 🟢 | ≥ 50% | 正常交付 |
| 🟡 | 20~49% | 提示偏低 |
| 🔴 | < 20% | 提供新對話開場白 |

**顯示格式**：`Token: {emoji} 剩餘: {pct}%`（一律置於回覆末尾）。

### 1.3 估算原則（公式為主）

**核心**：**無平台顯示，以公式計算為主**。

| # | 規則 |
|---|---|
| 1 | 一律以公式計算（§一.4）為主 |
| 2 | 若未來有 API `usage` → 優先採用 |
| 3 | 若未來有平台顯示 % → 優先採用 |
| 4 | 公式計算是目前唯一可用方法 |

**低於 20% 強制重估（D-102 修正）**：

| # | 規則 |
|---|---|
| 1 | 若公式估算 < 20% → 不得直接報告，必須重估 |
| 2 | 重估採不同方法（如：對話字數 vs 1M 窗口 / 累積輸入 / 累積輸出） |
| 3 | 重估後仍 < 20% → 才可報告 |
| 4 | 以「內容總量 vs 窗口」為主 |

### 1.4 參考公式

**DeepSeek 官方換算依據**：

| 類型 | 比例 |
|---|---|
| 中文 | 1 字 ≈ 0.6 Token |
| 英文 | 1 字元 ≈ 0.3 Token |
| 數字 / 符號 | 1 個 ≈ 1 Token |

**總量公式**：`總 Token = 輸入 Token + 輸出 Token`

**每行 Token（由官方比例推導）**：

| 檔案類型 | 每行 token |
|---|---|
| .md 表格 | ~18 |
| .md 敘述 | ~12 |
| .js 程式碼 | ~15 |
| .css | ~8 |
| .html | ~10 |
| .json | ~10 |

**對話輸入總量**：

> **輸入（累積） = k × N² / 2**

| 符號 | 說明 |
|---|---|
| k | 每輪平均新增 token |
| N | 對話輪數 |

**輸出總量**：

> **輸出 = 全部回覆的 token 總和**

**上下文窗口需求**：

> **窗口需求 = 全部上傳內容 + 全部回覆**

**DeepSeek-V4 窗口**：1M token

**計費總量**：

> **計費 ≈ 窗口需求 × 30~40 倍**

### 1.5 記錄格式

| 欄位 | 說明 |
|---|---|
| 批次 | 當前批次號 |
| 對話編號 | 本次對話的編號 |
| 對話輪數 N | 對話的總輪數 |
| 每輪平均新增 k | 全部上傳 + 回覆 ÷ N |
| 輸入累積 | k × N² / 2 |
| 輸出總量 | 全部回覆 token 和 |
| 窗口需求 | 上傳 + 回覆 |
| 窗口佔用 % | 窗口需求 / 1M |
| 估算剩餘 % | 100% − 窗口佔用 % |
| 實際狀態 | 使用者反饋 |
| 誤差 | 估算 % − 實際 % |
| 校正係數 | 下次估算乘數 |

### 1.7 校正公式

| 項目 | 公式 |
|---|---|
| 輸入累積 | k × N² / 2 |

## 三、交接快照機制（C-10 無損合併）

### 3.1 目的

| 項目 | 說明 |
|---|---|
| 問題 | 對話結束後，下一 AI 需快速接手 |
| 解法 | 產出交接快照（≤ 80 行） |
| 用途 | 保留進度與下一步，不需翻對話 |

### 3.2 機制規則（D-016 / D-018 / D-024 / D-026）

| 項目 | 規則 |
|---|---|
| 觸發 | 對話即將結束時 |
| 產出 | 交接快照（≤ 80 行） |
| 內容 | 進度 / 決策 / 下一步 / 重建條件 |
| 禁止 | 超過 80 行 |
| 觸發詞 | 使用者說「結束對話」 |

### 3.3 機制與內容分離（D-041 / D-103）

### 3.6 重建條件（D-024）

**核心**：交接快照不是「狀態」，而是「向前指向的重建條件」。

| 概念 | 說明 |
|---|---|
| 狀態快照 | 現在有什麼（過去式） |
| 重建條件 | 下一 AI 應優先確認什麼（未來式） |

**範例**：

| # | 下一 AI 優先確認 |
|---|---|
| 1 | 議題 7 是否已結案 |
| 2 | 共享包是否為最新 |
| 3 | 未完成事項是否已排程 |
