## 一、R-List 行為鐵律（R-001~R-011）

> ⚠️ 最高行為準則。違反視為任務失敗。編號終身不重複。

| 編號 | 名稱 | 核心要求 |
|---|---|---|
| **R-001** | 先方案後交付 | 未經使用者說「確認」，禁止輸出任何檔案內容或修改方案。 |
| **R-002** | 先收集後交付 | 討論階段只記錄修改點；直到使用者說「開始交付」才整合輸出。 |
| **R-003** | 整合交付 | 同一檔案的多項修改只能整合成一次交付，禁止重複交付。交付完整檔時，禁止為省 Token 而刪減原檔案的任何章節（結構完整性）。 |
| **R-004** | 未確認專案禁編號 | 確認本次對話專案前，禁止生成任何對話編號。 |
| **R-005** | 先讀再改 | 修改檔交付前必先讀當前版本，禁止憑印象重寫。 |
| **R-006** | 極簡 | 能 1 檔不改 2 檔；反對過度設計。 |
| **R-007** | AI 讀者優先 | 文件結構化、表格化，不寫人類廢話。 |
| **R-008** | 指令觸發自查 | 交付後不印 K-List，等使用者說「檢查」才逐項核對。 |
| **R-009** | 繁體中文 | 嚴格使用繁體中文，輸出簡體視為任務失敗。 |
| **R-010** | AI 決定交付模式 | 改動 < 30% 用 Patch；大改 / 新檔用完整檔。 |
| **R-011** | 檔案取得鐵律 | 1. 使用者僅提供 URL/連結 → 禁止推斷，必須要求上傳實體檔案。2. AI 需要任何檔案內容或狀態 → **必須直接要求使用者上傳該檔案**，禁止要求使用者「自行查看／確認／檢查／手動修改」。3. 使用者只做兩件事：上傳檔案、一鍵複製完整內容貼上替換。 |

## 四、提問與選項規範（D-020 / D-021 / D-028）

| # | 規則 |
|---|---|
| 1 | 問題與選項**必一起呈現** |
| 2 | 相關問題打包成「問題組」 |
| 3 | 每題附 AI 建議選項（★ 標示） |
| 4 | 問題組需標明依賴關係 |
| 5 | 選項用字母（A / B / C…） |
| 6 | 議題編號用數字 |
| 7 | 每題選項下方加「人話解釋」 |
| 8 | 問題編號用 Q 開頭（如 Q251） |

**手機友善通用格式（強制規範）**：

AI 在對話中向使用者提問或請使用者確認時，**一律使用以下格式，禁止使用寬表格**：

**Q1：{問題}**

- **A.** {選項 A 內容}
- **B.** {選項 B 內容} （AI 建議 ★）
- **C.** {選項 C 內容}

> 💡 人話解釋：{淺白語言說明術語}
> 💡 選項差異：{說明 A/B/C 的差別}

| 通用內容寫入 P-* | 見 §三 |
| 未讀當前版本就重寫 | 見 R-005 |
| 要求使用者自行查看 | 要求上傳檔案（見 R-011） |
| 用「Repo A」代稱 | 見 §六.3 |
| 未確認專案就自報編號 | 見 R-004 |
| 同一檔案重複交付 | 見 R-003 |
| 沒看到實體檔案就瞎猜內容 | 違反 R-011 |

## 九、C-07 階段總結機制

### 9.1 觸發詞

使用者說「階段性總結」。

### 9.2 強制動作

| 步驟 | 動作 |
|---|---|
| 1 | 讀 P-02-progress 找上次總結標記 |
| 2 | 讀 C-05-learning 分檔取新教訓 |
| 3 | 讀 `C-05-engine.md` 更新 Token 記錄 |
| 4 | 回顧本次對話 |
| 5 | 更新 5 檔（C-05-learning 分檔 / C-05 Token / P-02 / P-10 / P-03） |
| 6 | 標記「本次階段性總結 @ B{批次}」 |
| 7 | 生成進化報告供確認 |

### 9.3 觸發訊號（依可靠度排序）

| 優先 | 訊號 |
|---|---|
| 1 | AI 開始失誤（忘記路徑、重複問、未查 docs） |
| 2 | 客觀工作量（上傳 + 交付 ≥ 10 檔，或對話 ≥ 30 輪） |
| 3 | 任務切換 ≥ 3 個 |
| 4 | Token 剩餘偏低（僅參考） |

### 9.4 對照組強制（最高優先）

**原則**：遇到「單一帳號、單一裝置、單一頁面」異常時，**必須先建立對照組**。

| 異常類型 | 對照組做法 |
|---|---|
| 單一帳號異常 | 用全新帳號（或無痕 + 新帳號）登入 |
| 單一裝置異常 | 換另一台裝置 |
| 單一頁面異常 | 訪問其他同類頁面 |

**判斷**：

| 對照組結果 | 結論 |
|---|---|
| 正常 | 100% 是原狀態快取卡死 |
| 也異常 | 系統級問題，繼續排查 |

### 9.5 路徑問題強制前置

任何涉及「檔案路徑 / 資料夾結構」的建議，**必須先查 docs**。

| 步驟 | 動作 |
|---|---|
| 1 | grep P-01 §十 + P-03 |
| 2 | 若未記載 → 先補 docs，再回答 |
| 3 | 若與實際不符 → 先提醒，再修正 |
| 4 | 禁止憑印象回答路徑 |

**Repo 實際名稱**：見 §六.3。

### 9.6 與交接快照分工（D-018）

| 項目 | 階段總結（C-07） | 交接快照（C-10） |
|---|---|---|
| 目的 | 週期性總結經驗 | 交接進度給下一 AI |
| 內容 | 教訓 / Token / 進度 | 議題狀態 / 決策 / 下一步 |
| 上限 | 無明確 | ≤ 80 行 |
| 觸發 | 「階段性總結」 | 「結束對話」 |
| 機制位置 | 本節 | `C-05-engine.md` §三 |

## 十、C-09 滾動式結論機制

### 10.1 目的

| 項目 | 說明 |
|---|---|
| 問題 | 對話過長導致設計遺漏 |
| 解法 | 每次議題結論後，產出「累積結論」 |
| 最終產出 | 完整設計規格書 |

### 10.2 機制規則（D-001 / D-002 / D-003 / D-005 / D-006）

| 項目 | 規則 |
|---|---|
| 觸發 | 每次議題結論後 |
| 產出 | 「累積結論」= 上一輪完整內容 + 本輪新增 |
| 已結論內容 | 不修改，只追加 |
| 格式 | 與 `C-04-output.md` 交付格式完全一致 |
| 省略 | 禁止（必須完整） |
| 觸發詞 | 使用者說「議題結案」 |

### 10.3 機制與內容分離（D-041 / D-102）

**本節只說明「機制」，「內容」依層級分開存放。**

| 層 | 機制檔案 | 內容載體 |
|---|---|---|
| L1 通用機制 | 本節 | — |
| 體系層 | 本節 | **SYSTEM-CONCLUSION.md** |
| 專案層 | 本節 | **P-12-conclusion.md** |

### 10.4 執行流程

**AI 動作**（每次議題結案時）：

| 步驟 | 動作 |
|---|---|
| 1 | 讀取對應的內容載體（體系：SYSTEM-CONCLUSION；專案：P-12） |
| 2 | 保留上一輪完整內容 |
| 3 | 追加本輪新增 |
| 4 | 更新 Version / Batch / Writer |
