## 一點五、估算原則（公式為主）

**核心**：**無平台顯示，以公式計算為主**。

| # | 規則 |
|---|---|
| 1 | 一律以公式計算（§二）為主 |
| 2 | 若未來有 API `usage` → 優先採用 |
| 3 | 若未來有平台顯示 % → 優先採用 |
| 4 | 公式計算是目前唯一可用方法 |

**低於 20% 強制重估（D-102 修正）**：

| # | 規則 |
|---|---|
| 1 | 若公式估算 < 20% → 不得直接報告，必須重估 |
| 2 | 重估採不同方法（如：對話字數 vs 1M 窗口 / 累積輸入 / 累積輸出） |
| 3 | 重估後仍 < 20% → 才可報告 |
| 4 | 以「內容總量 vs 窗口」為主 |

## 二、參考公式

### 2.1 DeepSeek 官方換算依據

| 類型 | 比例 |
|---|---|
| 中文 | 1 字 ≈ 0.6 Token |
| 英文 | 1 字元 ≈ 0.3 Token |
| 數字 / 符號 | 1 個 ≈ 1 Token |

**總量公式**：`總 Token = 輸入 Token + 輸出 Token`

### 2.2 每行 Token（由官方比例推導）

| 檔案類型 | 每行 token |
|---|---|
| .md 表格 | ~18 |
| .md 敘述 | ~12 |
| .js 程式碼 | ~15 |
| .css | ~8 |
| .html | ~10 |
| .json | ~10 |

### 2.3 對話輸入總量

> **輸入（累積） = k × N² / 2**

| 符號 | 說明 |
|---|---|
| k | 每輪平均新增 token |
| N | 對話輪數 |

### 2.4 輸出總量

> **輸出 = 全部回覆的 token 總和**

### 2.5 上下文窗口需求

> **窗口需求 = 全部上傳內容 + 全部回覆**

**DeepSeek-V4 窗口**：1M token

### 2.6 計費總量

> **計費 ≈ 窗口需求 × 30~40 倍**

## 三、記錄格式

| 欄位 | 說明 |
|---|---|
| 批次 | 當前批次號 |
| 對話編號 | 本次對話的編號 |
| 對話輪數 N | 對話的總輪數 |
| 每輪平均新增 k | 全部上傳 + 回覆 ÷ N |
| 輸入累積 | k × N² / 2 |
| 輸出總量 | 全部回覆 token 和 |
| 窗口需求 | 上傳 + 回覆 |
| 窗口佔用 % | 窗口需求 / 1M |
| 估算剩餘 % | 100% − 窗口佔用 % |
| 實際狀態 | 使用者反饋 |
| 誤差 | 估算 % − 實際 % |
| 校正係數 | 下次估算乘數 |
