## 一、用途

| 項目 | 說明 |
|---|---|
| 問題 | AI 對 Token 剩餘量的估算不準確 |
| 解法 | 以平台顯示為準；公式為輔 |
| 目標 | 累積數據後校正估算，使誤差 < 10% |

## 一點五、最高原則（Q2 A，B34-2）

**核心**：**以 API 回傳 `usage` 欄位為準**。

| # | 規則 |
|---|---|
| 1 | 精確數字一律以 API `usage` 為準 |
| 2 | 無 `usage` 時 → 以平台顯示 % 為準 |
| 3 | 無平台顯示 → **不自行報具體 %**，只說「充足 / 偏低 / 需注意」 |
| 4 | 公式僅作粗略參考，不作交付依據 |

**低於 20% 強制重估（D-102）**：

| # | 規則 |
|---|---|
| 1 | 若估算 < 20% → 不得直接報告，必須重估 |
| 2 | 重估採不同方法（窗口佔用 / 累積計費 / 平台顯示） |
| 3 | 重估後仍 < 20% → 才可報告 |
| 4 | 無平台顯示 → 以「內容總量 vs 窗口」為主 |

## 二、參考公式

### 2.1 DeepSeek 官方換算依據（Q1 A，B34-2）

| 類型 | 比例 |
|---|---|
| 中文 | 1 字 ≈ 0.6 Token |
| 英文 | 1 字元 ≈ 0.3 Token |
| 數字 / 符號 | 1 個 ≈ 1 Token |

**總量公式**：`總 Token = 輸入 Token + 輸出 Token`

**權威來源**：API 回傳 `usage` 欄位。

### 2.2 每行 Token（由官方比例推導）

| 檔案類型 | 每行 token | 推導依據 |
|---|---|---|
| .md 表格 | ~18 | 中文 ~30 字 × 0.6 |
| .md 敘述 | ~12 | 中文 ~20 字 × 0.6 |
| .js 程式碼 | ~15 | 英文 ~50 字元 × 0.3 |
| .css | ~8 | — |
| .html | ~10 | — |
| .json | ~10 | — |

### 2.3 對話輸入總量

> **輸入（累積） = k × N² / 2**

| 符號 | 說明 |
|---|---|
| k | 每輪平均新增 token |
| N | 對話輪數 |

### 2.4 輸出總量

> **輸出 = 全部回覆的 token 總和**（不乘輪數）

### 2.5 上下文窗口需求

> **窗口需求 = 全部上傳內容 + 全部回覆**

### 2.6 計費總量

> **計費 ≈ 窗口需求 × 30~40 倍**

## 三、記錄格式

| 欄位 | 說明 |
|---|---|
| 批次 | 當前批次號 |
| 對話輪數 N | 從上次總結到本次總結的輪數 |
| 每輪平均新增 k | 全部上傳 + 回覆 ÷ N |
| 輸入累積 | k × N² / 2 |
| 輸出總量 | 全部回覆 token 和 |
| 估算剩餘 % | 平台顯示 |
| 實際狀態 | 使用者反饋 |
| 誤差 | 估算 % − 實際 % |
| 校正係數 | 下次估算乘數 |

## 五、校正公式

| 項目 | 公式 |
|---|---|
| 輸入累積 | k × N² / 2 |
