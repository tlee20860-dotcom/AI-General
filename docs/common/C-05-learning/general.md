## 二、教訓（依時間倒序）

### [L-025] [all] 路徑顯示未依操作場景區分

| 項目 | 內容 |
|---|---|
| 場景 | 交付新增檔時，給「含倉庫名」路徑；使用者在 GitHub 網頁貼上 → 變雙層目錄 |
| 錯誤 | 未提示「網頁操作勿加倉庫名」 |
| 正確 | 本機 git / Spck → 含倉庫名；GitHub 網頁 → 只用倉庫內相對路徑 |
| 適用規則 | C-04 §一點一 |

### [L-024] [all] 交付新增檔案路徑未用 code block

| 項目 | 內容 |
|---|---|
| 場景 | 交付新增檔 `C-05-learning/general.md` 時，路徑用純文字 |
| 錯誤 | 照抄「修改檔」格式，未切換 |
| 正確 | 新增 / 改名 / 刪除 → code block；修改 → 純文字 |
| 適用規則 | C-04 §一 |

### [L-021] [all] Token 估算反覆過度保守

| 項目 | 內容 |
|---|---|
| 場景 | 對話 A20261013-004，全程多次報「剩 8~16%」 |
| 錯誤 | 未依 D-102 重估，過度保守誤判；實際剩 30~40% |
| 正確 | 若估算 < 20% → 強制重估（採不同方法）；以平台顯示為準 |
| 適用規則 | C-02 §零點五（D-102） |

### [L-019] [all] 交付修改檔未先看當前版本

| 項目 | 內容 |
|---|---|
| 場景 | 交 `ui/modal.js` 修改版（#092） |
| 錯誤 | 未先讀當前 modal.js（v103.0.23），刪除了原有堆疊 / bindModals / destroyModal |
| 正確 | 交付前必須先讀當前版本，只做最小改動 |
| 適用規則 | C-02 §四之一 |

### [L-018] [all] 交付修改檔未標明 base version

| 項目 | 內容 |
|---|---|
| 場景 | 交 `sw.js` 修改版（#097） |
| 錯誤 | 只說「修改」，未標示基於哪個版本 |
| 正確 | 交付時標明「基於 #NNN 的 vX.Y.Z」 |
| 適用規則 | C-04 §一點五（D-101） |

### [L-017] [all] 議題編號與回覆選項混淆

| 項目 | 內容 |
|---|---|
| 場景 | 使用者說「討論第 6 項」，AI 誤以為議題 6 |
| 錯誤 | 未確認使用者指「議題 6」還是「回覆選項 6」 |
| 正確 | 議題用數字、選項用字母；提問必附選項 |
| 適用規則 | C-02 §二之一、§9.4 |

### [L-016] [all] Token 顯示格式與位置不一致

| 項目 | 內容 |
|---|---|
| 場景 | 不同對話 Token 顯示格式與位置不同 |
| 錯誤 | 舊對話用進度條 + 位置不一致 |
| 正確 | 固定格式「Token: {emoji} 剩餘: {pct}%」，位置一律回覆末尾 |
| 適用規則 | C-02 §零點五 |

### [L-015] [all] md 檔案內誤用三反引號

| 項目 | 內容 |
|---|---|
| 場景 | 交付 .md 檔案，內含格式範例 |
| 錯誤 | 用三反引號包裹，渲染成灰框干擾 |
| 正確 | md 內零三反引號；範例用引用塊 |
| 適用規則 | C-02 §六點五 |

### [L-014] [all] Spck Editor 手動上傳檔案失誤

| 項目 | 內容 |
|---|---|
| 場景 | 使用 Spck Editor 手動修改並推送 GitHub |
| 錯誤 | 把 A 檔案的代碼貼到 B 檔案 |
| 正確 | 每次推送前，逐一核對「檔名 ↔ 內容」 |
| 適用規則 | C-02 §十七 |
