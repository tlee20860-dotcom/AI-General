## 一、開場 SOP

**AI 讀 C-00-startup 後**：

| 步驟 | 動作 |
|---|---|
| 1 | 回報「已讀取 startup」 |
| 2 | 回報共享包「構建編號」與「生成時間」，問使用者是否為最新 |
| 3 | **確認本次對話所屬專案後**，生成對話編號（見 C-00 §三、防呆 §3.4） |
| 4 | 自報編號 |
| 5 | 依議題表驅動制提示下一議題（見 §七之三） |
| 6 | 列 4 選項 |
| 7 | 待使用者選擇 |

**⚠️ 防呆**：步驟 1~2 不得生成任何編號；步驟 3 才生成。

**議題表驅動提示範例**：

> 🆔 ai-system-20261016-005 #001
>
> 已讀取 startup 檔。
> 本包構建編號：#0043，生成於 2026-10-16 18:30 UTC。
> 建議下一議題：議題 7（新專案模板）
>
> 請告知本次情境：
> 1. 新專案 2. 舊專案 3. 純討論 4. 其他

### 1.1 使用者選「新專案」

| 步驟 | 動作 |
|---|---|
| 1 | **AI 先問領域**（見 C-00 §十一） |
| 2 | 使用者回答領域 |
| 3a | 已有領域 → 直接開新專案 |
| 3b | 新領域 → AI 主動建議建 `{X}-*` 6 檔 |
| 4 | 使用者確認 → 產出 6 檔草稿 |
| 5 | 依回饋迭代 |
| 6 | **產出該專案 `notify.yml`** |

### 1.2 使用者選「舊專案」

| 步驟 | 動作 |
|---|---|
| 1 | AI 說「請上傳對應編號的共享包（如 01-CORE-SYSTEM.md 或 02-CORE-PROJECT.md + 90-{專案}.md）」 |
| 2 | 使用者上傳共享包 |
| 3 | AI 讀取 |
| 4 | 依進度繼續 |

### 1.3 使用者選「純討論」

AI 說「請描述問題」。

## 五、對話流程（典型）

### 5.1 體系層對話

| 步驟 | 誰 | 動作 |
|---|---|---|
| 1 | 你 | 上傳 01-CORE-SYSTEM.md |
| 2 | AI | 讀取 + 回報構建編號 + 列所有專案 |
| 3 | 你 | 說要哪個專案 |
| 4 | AI | 生成編號 + 提示議題 + 列 4 選項 |
| 5 | 你 | 選情境 |

| 7 | 你 | 說明需求 |
| 8 | AI | 分析 + 方案 |
| 9 | 你 | 確認（只記錄） |
| 10 | 你 | 說「開始交付」 |
| 11 | AI | 列清單 |
| 12 | 你 | 說「確認清單」 |
| 13 | AI | 逐批交付 |

## 七之六、新增專案流程（Q1~Q6）

**觸發**：使用者說「新增專案」。

### 第一步：AI 一次列出 Q1~Q6（含人話說明）

> 請提供以下資訊，我會逐一處理：

**Q1：專案英文名稱？**

> 這會成為目錄名稱與倉庫名稱，只能用英文小寫與連字號。

- A. 自訂（請直接輸入英文名稱）
  > 人話：你自己取名，例如「vba-accounting」。

- B. 由 AI 根據顯示名稱自動生成（推薦）
  > 人話：你只要在 Q2 給中文名，AI 幫你翻成英文。

**Q2：專案顯示名稱？**

> 這是你在對話中看到的中文名稱。

- A. 自訂（請直接輸入中文名稱）
  > 人話：你自己取中文名，例如「VBA 會計系統」。

- B. 由 AI 根據英文名稱自動生成
  > 人話：如果 Q1 已取英文名，AI 幫你翻成中文。

**Q3：專案領域？**

> 領域決定這個專案使用哪套技能包。

- A. W（Web App）
  > 人話：網頁應用。

- B. V（VBA / 桌面自動化）
  > 人話：Excel VBA、Office 自動化腳本。

- C. D（資料分析 / 腳本）
  > 人話：Python 資料分析、自動化腳本。

- D. M（文案 / 內容創作）
  > 人話：寫文案、SEO 文章、社群內容。

- E. 其他（請說明）
  > 人話：以上都不是，請你告訴我這個專案屬於什麼類型。

**Q4：倉庫可見性？**

- A. Public（公開）
  > 人話：任何人都能看到。

- B. Private（私有，推薦）
  > 人話：只有你能看到。

**Q5：是否由 Actions 自動建立倉庫？**

- A. 是（推薦）
  > 人話：更新專案清單，Actions 就自動建好倉庫。

- B. 否
  > 人話：你自己去 GitHub 建立倉庫。

**Q6：新倉庫的初始內容？**

- A. 只有 README.md
  > 人話：最精簡。

- B. README.md + .gitignore（推薦）
  > 人話：說明檔 + 忽略規則。

- C. README.md + .gitignore + 基本目錄結構
  > 人話：再加上 js/、css/ 等基本目錄。

### 第二步：等使用者回答

### 第三步：報告準備新增的專案，等使用者確認

### 第四步：吐出完整 PROJECT-LIST.md

### 第五步：提示使用者貼到 `docs/records/PROJECT-LIST.md`

### 第六步：AI 產出對應的 `notify.yml`（提示使用者貼到新 repo）

### 第七步：Actions 自動執行

| # | 動作 |
|---|---|
| 1 | 建立新倉庫（依 Q4、Q5、Q6） |
| 2 | 建立 `docs/projects/{新專案}/` 與 `P-00-{name}.md` |
| 3 | 生成共享包（含新專案） |

## 九、常見錯誤（禁止）

| 錯誤 | 正確 |
|---|---|
| 未經確認直接改檔 | 先方案 |
| 直接估算 N 檔 | 先掃描 |
| 從現況推論範圍 | 從理想推論 |
| 忽略使用者偏好 | 讀 C-01 |
| 忘記記錄教訓 | 對話結束綜合 |
| 忘記顯示 Token 狀態 | 見 C-02 §零點五 |
| 問題與選項分開 | 見 C-02 §二之一 |
| 議題編號與選項混淆 | 見 C-02 §9.4 |
| 通用內容寫入 P-* | 見 C-02 §零點八 |
| 未讀當前版本就重寫 | 見 C-02 §四之一 |
| 用「Repo A」代稱 | 見 C-02 §十三之一 |
| 未確認專案就自報編號 | 見 C-00 §3.4 |
| 同一檔案重複交付 | 見 C-02 §19.2 |
