## 零、F-List 格式規範

| 編號 | 名稱 | 規範要求 |
|---|---|---|
| **F-001** | **對話標頭** | AI 在對話框交付時，必須附上專案、類型、編寫者。**此標頭嚴禁寫入檔案內部**。 |
| **F-002** | **路徑顯示** | 路徑一律用「倉庫內相對路徑」，且必須用 **Code Block** 包裹，倉庫名用純文字。 |
| **F-003** | **外層包裹** | 檔案內容必須用「三反引號 + 語言標示」包裹。 |
| **F-004** | **內層防呆** | md 檔案內部禁止使用三反引號。範例請用引用塊（>）或表格。 |
| **F-005** | **檔案結尾** | 檔案底部必須包含 EOF 標記：F/V/B/W。 |
| **F-006** | **狀態總表** | 每次交付後，必須附上「檔案狀態總表」。 |

## 一、交付格式

### 1.1 每檔交付（F-001 對話標頭）

**標題格式**（純文字，禁用三反引號）：

> ## 交付路徑：
> 📁 倉庫：{倉庫名稱}
> 📂 路徑：
>
> （以下用 code block）
>
> {倉庫內相對路徑}
>
> （以上 code block 結束）
>
> 📂 所屬專案：{專案名稱}
>
> ## 交付內容：
> 📄 {檔案內容(類別)}
> 🔄 交付類型：新增 / 修改 / 刪除
> 👤 編寫者：{編號}
> 📌 基於版本：（僅修改檔需要）
> （| {Unix_epoch} | {YYYY-MM-DD HH:mm}）

**路徑顯示規則**：

| 項目 | 顯示方式 |
|---|---|
| 倉庫名稱 | 純文字 |
| 路徑 | **Code Block**（方便一鍵複製） |
| 所屬專案 | 純文字 |

**路徑寫法**：一律用「**倉庫內相對路徑**」。

| 場景 | 正確 | 錯誤 |
|---|---|---|
| 所有操作（本機 / Spck / GitHub 網頁） | `docs/common/C-00-startup.md` | `AI-General/docs/common/C-00-startup.md` |

> ⚠️ **勿在路徑前加倉庫名稱**，否則會變成雙層目錄（如 `AI-General/AI-General/docs/...`）。

**檔案內容**：**必須用三反引號包裹**（附語言標示）

| 檔案 | 語言標示 |
|---|---|
| .js | js |
| .md | md |
| .json | json |
| .css | css |
| .html | html |
| .txt | text |

### 1.2 批次交付開頭

**格式**（純文字）：

> 📦 B{n}：第 {N}/{M} 批（{X} 檔）
>
> 交付時間：YYYY-MM-DD HH:mm
> Unix epoch：{10 位}
> 編寫者：{對話編號}#{回覆序號}

**對話編號格式**：{專案代碼}-{YYYYMMDD}-{專案內序號3位}

## 二、Base Version 標示（D-101）

**核心**：**修改檔必標 base version**（L-018 教訓）。

| # | 規則 |
|---|---|
| 1 | 交付「修改檔」時，必標「基於 #NNN 的 vX.Y.Z」 |
| 2 | 若無明確 base → 標「基於既有 vX.Y.Z」 |
| 3 | 「新增檔」不需標 base |
| 4 | 改動摘要須列「新增 / 修改 / 刪除什麼」 |

---

## 三、兩層三反引號規則（F-003 / F-004）

**核心**：分「外層」與「內層」。

### 3.1 外層（AI 交付時）

| 情境 | 寫法 |
|---|---|
| AI 交付任何檔案內容 | **必須用三反引號包裹** |
| 目的 | 提供「一鍵複製」按鈕 |

**禁止**：直接寫（不包裹）→ 使用者無法一鍵複製。

### 3.2 內層（md 檔案內部）

| 情境 | 寫法 |
|---|---|
| md 內展示格式 / 範例 | 引用塊（>） |
| md 內單行關鍵字 | 行內單反引號 |
| md 內結構化內容 | markdown 表格 |
| md 內真代碼 | 另存獨立檔案 |

**禁止**：md 內用三反引號。

### 3.3 內層（真代碼檔案）

| 情境 | 寫法 |
|---|---|
| .js / .html / .css 內含三反引號 | 正常 |
| .js 內若需展示含三反引號的範例 | 外層 = 內層最多 + 1 |

---

## 四、END OF FILE 格式（F-005）

**格式**（引用塊呈現，非三反引號）：

> /\* ═══ EOF ═══
> F: 完整路徑
> V: Unix epoch
> B: 批次號
> W: 編寫者#序號
> ═══ \*/

| 縮寫 | 全稱 |
|---|---|
| F | File |
| V | Version |
| B | Batch |
| W | Writer |

**註解符號**：

| 檔案 | 符號 |
|---|---|
| .js / .css | 斜線星號（成對） |
| .md | 斜線星號 或 HTML 註解 |
| .html | HTML 註解 |
| .json | 不支援 |
| .yml / .yaml | 井號（#） |

## 五、單行索引

**每批交付開頭附**：

> 📦 B32-2 [1791886800]
>
> docs/C-02-rules.md      V:1791886800 W:webapp-20261016-001#014

**編寫者格式**：{對話編號}#{回覆序號}

## 六、檔案狀態總表（F-006）

每次有修改點時，AI 在回覆末尾顯示此表。

**格式**：

| # | 檔案路徑 | 狀態 | 修改項 | 交付編號 |
|---|---|---|---|---|
| 1 | docs/common/C-02-rules.md | ⏳ 待交付 | 加入規則X | — |
| 2 | docs/common/C-05-engine.md | ✅ 已交付 | 加入詞彙 | webapp-20261016-001#003 |

**狀態定義**：

| 狀態 | 標記 | 意義 |
|---|---|---|
| 討論中 | 💬 | 已記錄修改項，尚未確認交付 |
| 待交付 | ⏳ | 已確認，等待交付 |
| 已交付 | ✏️ | AI 已交付，等你更新 |
| 已更新 | ✅ | 你已貼到 GitHub |
| 方案已改 | 🔄 | 需重新交付 |
| 已廢棄 | 🗑️ | 不再使用 |

**顯示時機**：

| 時機 | 動作 |
|---|---|
| 有修改點時 | 顯示 |
| 每 5 輪 | 主動回顧一次 |
| 交付前 | 逐項確認一次 |

## 七、交付類型標示

| 標示 | 含義 |
|---|---|
| （新增） | 全新檔案 |
| （修改） | 完整替換舊檔 |
| （刪除） | 刪除檔案 |
| （片段 - 違反規則） | 只給片段（例外） |

## 八、backtick 嵌套規則

| 內層最多 | 外層 |
|---|---|
| 3 個 | 4 個 |
| N 個 | N + 1 個 |

**md 檔案內**：遵守 §三（零三反引號）。

## 九、常見格式錯誤

| # | 錯誤 | 正確 |
|---|---|---|
| 1 | 只給 diff | 完整檔案（或合法 Patch） |
| 2 | 用「...」「同上」 | 完整列出 |
| 3 | 多檔合併 | 每檔獨立 |
| 4 | 內層三反引號 | 外層 = 內層 + 1 |
| 5 | 忘 EOF | 必加 |
| 6 | 檔案 > 800 行 | 拆檔 |
| 7 | 忘 Token 狀態 | 見 C-05 §一.2 |
| 8 | 未標交付類型 | 必標 |
| 9 | 未附狀態總表 | 必附 |
| 10 | 未附單行索引 | 必附 |
| 11 | Version 用舊制 | 用 Unix epoch |
| 12 | 未標編寫者 | 必標 |
| 13 | md 內用三反引號 | 改引用塊 |
| 14 | 交付時未用三反引號包裹 | 必須包裹 |
| 15 | 修改檔未標 base version | 必標（D-101） |
| 16 | 未讀當前版本就重寫 | 先讀（R-005） |
| 17 | 路徑前誤加倉庫名稱 | 只用倉庫內相對路徑（L-025） |
| 18 | 未標所屬專案 | 必標 |
| 19 | 交付不完整（以 Token 為理由偷懶） | 必完整（C-05 §一） |
| 20 | 路徑未用 code block | 路徑一律 code block（L-024） |

## 十一、交付前自我檢查與強制勾選

**核心**：**每次交付完整檔案時，AI 必須在回覆末尾輸出完整的檢查表，並將所有項目標記為 ✅。**
這用來防止 AI 在長對話或 Token 不足時，偷偷刪減內容或跳過步驟。

**檢查表（交付時必附）**：

| 檢查項目 | 狀態 |
|---|---|
| 1. 路徑為倉庫內相對路徑（無倉庫名前綴） | ✅ |
| 2. 內容完整，無「前略」、「同上」等省略字眼 | ✅ |
| 3. 內容用三反引號包裹（外層） | ✅ |
| 4. 含 EOF（F/V/B/W） | ✅ |
| 5. md 內零三反引號（內層） | ✅ |
| 6. 交付類型已標示 | ✅ |
| 7. 所屬專案已標示 | ✅ |
| 8. 編寫者已標 | ✅ |
| 9. 修改檔已標 base version（D-101） | ✅ |
| 10. 已先讀當前版本（R-005） | ✅ |
| 11. 已跑 S-List | ✅ |
| 12. 已掃描實際檔數 | ✅ |
| 13. 單行索引已附 | ✅ |
| 14. 檔案狀態總表已附 | ✅ |
| 15. Token 狀態已顯示 | ✅ |
| 16. 已依 R-010 判斷完整檔或 Patch | ✅ |

## 十三、K-List 事後檢查

> ⚠️ 依 R-008：交付後**不主動**印出。僅當使用者下達「檢查」指令時，AI 才印出本清單，針對剛才交付的檔案逐項核對並回報 ✅ 或 ❌。

| 編號 | 檢查項目 | 對應規範 |
|---|---|---|
| **K-001** | 對話標頭檢查（專案、類型、編寫者齊全，未寫入檔內） | F-001 |
| **K-002** | 路徑顯示檢查（相對路徑且用 Code Block） | F-002 |
| **K-003** | 包裹與內層檢查（外層有、內層無） | F-003, F-004 |
| **K-004** | 結尾與版本檢查（有 EOF、有 Base version） | F-005 |
| **K-005** | 行為與內容檢查（未違反 R-List、無簡體、無省略） | R-001 ~ R-010 |

## 十四、Patch 模式（R-010 配套）

**核心**：依 R-010 判斷交付模式。

| 模式 | 觸發條件 | AI 動作 |
|---|---|---|
| **完整檔案** | 改動 ≥ 30% 或全新檔案 | 輸出完整內容。 |
| **Patch 替換** | 改動 < 30% | 輸出 Patch 格式，交由 Action 替換。 |

### 14.1 Patch 格式標準

> # PATCH 指令
>
> ## 修改目標
> `docs/common/目標檔案.md`
>
> ## 替換內容
> <<<<<<< OLD
> （舊文字）
> =======
> （新文字）
> >>>>>>> NEW

**Action 防護機制**：如果 `OLD` 字串在目標檔案中出現 0 次或超過 1 次，Action 會報錯並停止替換。

**Patch 使用規則**：

| # | 規則 |
|---|---|
| 1 | 改動 < 30% 才用 Patch |
| 2 | `OLD` 字串必須在目標檔中**唯一出現** |
| 3 | 新檔 / 大改一律用完整檔 |
| 4 | 兩階段確認已廢除，Patch 交付後等使用者說「檢查」才印 K-List |

**F-007：Patch 嚴格生成規範（AI 必守鐵律）**：

| # | 鐵律 | 說明 |
|---|---|---|
| 1 | **長度極限** | 單一 `OLD`/`NEW` 區塊，實際內容**不超過 3 行**。 |
| 2 | **唯一特徵** | 必須包含 Emoji、特殊符號（如 `>`、`#`、`|`），確保字串在檔案中唯一。 |
| 3 | **禁止空行** | 區塊內**絕對禁止**包含空行，防止換行符號導致匹配失敗。 |
| 4 | **精準對標** | 交付前必先讀取當前檔案，精準複製當下原始碼的縮排與符號。 |
| 5 | **拆解原則** | 長段落修改請拆成多個小區塊，一個 `FILE` 底下可有多組 `OLD/NEW`。 |

## 十五、批次號規則
