## 零、交付格式規範清單（F-List）

> ⚠️ 所有檔案交付必須嚴格遵守以下格式。編號終身不重複。

| 編號 | 名稱 | 規範要求 |
|---|---|---|
| **F-001** | **相對路徑** | 只寫倉庫內相對路徑（如 `docs/common/C-01.md`），禁止包含倉庫名稱。 |
| **F-002** | **外層包裹** | 檔案內容必須用「三反引號 + 語言標示」包裹（如 ```markdown）。 |
| **F-003** | **內層防呆** | md 檔案內部禁止使用三反引號。範例請用引用塊（>）或表格。 |
| **F-004** | **檔案結尾** | 檔案底部必須包含 EOF 標記：F/V/B/W。 |
| **F-005** | **版本標示** | 修改檔交付時，標題區必須標示 `基於版本`（Base version）。 |
| **F-006** | **狀態總表** | 每次交付後，必須附上「檔案狀態總表」。 |

## 一、實質檢查清單（K-List）

> ⚠️ 當使用者下達「檢查」指令時，AI 必須印出本清單，針對剛才交付的檔案逐項核對並回報 ✅ 或 ❌。

| 編號 | 檢查項目 | 對應規範 |
|---|---|---|
| **K-001** | 路徑格式檢查（無倉庫名前綴） | F-001 |
| **K-002** | 包裹與內層檢查（外層有、內層無） | F-002, F-003 |
| **K-003** | 結尾與版本檢查（有 EOF、有 Base version） | F-004, F-005 |
| **K-004** | 行為防呆檢查（未違反先方案後交付等 R-List） | R-001 ~ R-010 |
| **K-005** | 內容完整檢查（無簡體字、無「前略」、「同上」） | R-007, R-009 |

## 二、交付模式判斷（R-010 配套）

| 模式 | 觸發條件 | AI 動作 |
|---|---|---|
| **完整檔案** | 改動幅度 > 30% 或全新檔案 | 輸出完整內容。 |
| **Patch 替換** | 改動幅度極小（如改錯字、加一行） | 輸出 Patch 格式，交由 Action 替換。 |

### 2.1 Patch 格式標準

AI 輸出 Patch 時，必須嚴格遵守以下格式（**使用引用塊示範，絕不使用三反引號**）：

> # PATCH 指令
>
> ## 修改目標
> `docs/common/目標檔案.md`
>
> ## 替換內容
> <<<<<<< OLD
> （這裡放要被替換的舊文字，必須包含足夠上下文，確保唯一性）
> =======
> （這裡放修改後的新文字）
> >>>>>>> NEW

**Action 防護機制**：如果 `OLD` 字串在目標檔案中出現 0 次或超過 1 次，Action 會報錯並停止替換，確保絕對不會改錯。

## 三、交付輔助與摘要

### 3.1 交付摘要（4 欄位）
每次交付必須附上：
1. **改動檔案數**：N
2. **最小改動路徑**：如何得出
3. **為何不是 N-1**：為何不能再少
4. **所屬專案**：AI 對話系統 / 家庭 webapp / 其他
