## 零、交付格式規範清單（F-List）

| 編號 | 名稱 | 規範要求 |
|---|---|---|
| **F-001** | **對話標頭** | AI 在對話框交付時，必須附上專案、類型、編寫者。**此標頭嚴禁寫入檔案內部**。 |
| **F-002** | **路徑顯示** | 路徑一律用「倉庫內相對路徑」，且必須用 **Code Block** 包裹，倉庫名用純文字。 |
| **F-003** | **外層包裹** | 檔案內容必須用「三反引號 + 語言標示」包裹（如 ```markdown）。 |
| **F-004** | **內層防呆** | md 檔案內部禁止使用三反引號。範例請用引用塊（>）或表格。 |
| **F-005** | **檔案結尾** | 檔案底部必須包含 EOF 標記：F/V/B/W。 |
| **F-006** | **狀態總表** | 每次交付後，必須附上「檔案狀態總表」。 |

## 一、對話標頭與路徑規範（F-001, F-002）

### 1.1 對話標頭
> 📂 所屬專案：{專案名稱}
> 
> ## 交付內容：
> 📄 {檔案內容(類別)}
> 🔄 交付類型：新增 / 修改 / 刪除
> 👤 編寫者：{編號}
> 📌 基於版本：（僅修改檔需要）
> （| {Unix_epoch} | {YYYY-MM-DD HH:mm}）

### 1.2 路徑顯示規則
| 項目 | 顯示方式 |
|---|---|
| 倉庫名稱 | 純文字 |
| 路徑 | **Code Block**（方便一鍵複製） |
| 所屬專案 | 純文字 |

**路徑寫法**：一律用「**倉庫內相對路徑**」。
> ⚠️ **勿在路徑前加倉庫名稱**，否則會變成雙層目錄。

## 二、實質檢查清單（K-List）

> ⚠️ 當使用者下達「檢查」指令時，AI 必須印出本清單，針對剛才交付的檔案逐項核對並回報 ✅ 或 ❌。

| 編號 | 檢查項目 | 對應規範 |
|---|---|---|
| **K-001** | 對話標頭檢查（專案、類型、編寫者齊全） | F-001 |
| **K-002** | 路徑顯示檢查（相對路徑且用 Code Block） | F-002 |
| **K-003** | 包裹與內層檢查（外層有、內層無） | F-003, F-004 |
| **K-004** | 結尾與版本檢查（有 EOF、有 Base version） | F-005 |
| **K-005** | 行為與內容檢查（未違反 R-List、無簡體、無省略） | R-001 ~ R-010 |

## 三、交付模式判斷（R-010 配套）

| 模式 | 觸發條件 | AI 動作 |
|---|---|---|
| **完整檔案** | 改動幅度 > 30% 或全新檔案 | 輸出完整內容。 |
| **Patch 替換** | 改動幅度極小 | 輸出 Patch 格式，交由 Action 替換。 |

### 3.1 Patch 格式標準
> # PATCH 指令
> 
> ## 修改目標
> `docs/common/目標檔案.md`
> 
> ## 替換內容
> <<<<<<< OLD
> （舊文字）
> =======
> （新文字）
> >>>>>>> NEW

**Action 防護機制**：如果 `OLD` 字串在目標檔案中出現 0 次或超過 1 次，Action 會報錯並停止替換。
