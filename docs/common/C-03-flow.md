## 零、對話 SOP 與狀態機

| 步驟 | 角色 | 動作 |
|---|---|---|
| 1 | AI | 讀取啟動包，回報構建編號。 |
| 2 | 使用者 | 選擇專案。 |
| 3 | AI | 生成編號（防呆 R-004），提示下一議題，停等「繼續」。 |
| 4 | 使用者 | 說「繼續」並提出需求。 |
| 5 | AI | 進入 `STATE_DISCUSS`，提供分析與方案。 |
| 6 | 使用者 | 確認方案。 |
| 7 | AI | **只記錄，不交付**（R-002）。 |
| 8 | 使用者 | 說「開始交付」→ 列清單。 |
| 9 | 使用者 | 說「確認清單」→ 逐批交付。 |

## 一、開場 SOP

**AI 讀 C-00-startup 後**：

| 步驟 | 動作 |
|---|---|
| 1 | 回報「已讀取 startup」 |
| 2 | 回報共享包「構建編號」與「生成時間」，問使用者是否為最新 |
| 3 | **確認本次對話所屬專案後**，生成對話編號（見 C-00 §一） |
| 4 | 自報編號 |
| 5 | 依議題表驅動制提示下一議題（見 §八） |
| 6 | 列 4 選項 |
| 7 | 待使用者選擇 |

**⚠️ 防呆**：步驟 1~2 不得生成任何編號；步驟 3 才生成。

**議題表驅動提示範例**：

> 🆔 ai-system-20261016-005 #001
>
> 已讀取 startup 檔。
> 本包構建編號：#0043，生成於 2026-10-16 18:30 UTC。
> 建議下一議題：議題 7（新專案模板）
>
> 請告知本次情境：
> 1. 新專案 2. 舊專案 3. 純討論 4. 其他

### 1.1 使用者選「新專案」

| 步驟 | 動作 |
|---|---|
| 1 | **AI 先問領域**（見 §九 Q1~Q6） |
| 2 | 使用者回答領域 |
| 3a | 已有領域 → 直接開新專案 |
| 3b | 新領域 → AI 主動建議建 `{X}-*` 6 檔 |
| 4 | 使用者確認 → 產出 6 檔草稿 |
| 5 | 依回饋迭代 |
| 6 | **索取「新建的 Repo 完整名稱」** |
| 7 | 更新 `setup-structure.yml` 的 `PROJECT_REPOS` |

### 1.2 使用者選「舊專案」

| 步驟 | 動作 |
|---|---|
| 1 | AI 說「請上傳對應編號的共享包（如 01-CORE-SYSTEM.md 或 02-CORE-PROJECT.md + 90-{專案}.md）」 |
| 2 | 使用者上傳共享包 |
| 3 | AI 讀取 |
| 4 | 依進度繼續 |

### 1.3 使用者選「純討論」

AI 說「請描述問題」。

## 二、情境決策樹與讀取路由

| 使用者情境 | AI 讀取目標 | 執行重點 |
|---|---|---|
| 「有問題 / 修 Bug」 | `P-99-errors-map.md` + `C-05-learning` | 跑 S-List、提供診斷與方案。 |
| 「新增功能」 | `P-03-manifest.md` | 評估影響範圍、跑 S-List。 |
| 「改版面」 | `P-06-pagemap.md` | 列出變更前後對照表。 |
| 「新專案」 | 觸發 §九 Q1~Q6 | 領域詢問、索取 Repo。 |
| 「修改體系規則」 | `C-00`, `C-02` | 提出 R-List 或流程修改方案。 |

**使用者說「新增功能」**：

| 步驟 | 讀取 |
|---|---|
| 1 | C-02 §零（S-List） |
| 2 | P-03-manifest |

**使用者說「改版面」**：

|---|---|
| 1 | C-02 |
| 2 | P-06-pagemap 版面章節 |

## 五、典型對話流程

### 5.1 體系層對話

| 步驟 | 誰 | 動作 |
|---|---|---|
| 1 | 你 | 上傳 01-CORE-SYSTEM.md |
| 2 | AI | 讀取 + 回報構建編號 + 依 STATE-INDEX 列專案 |
| 3 | 你 | 說要哪個專案 |
| 4 | AI | 生成編號 + 提示議題 + 列 4 選項 |
| 5 | 你 | 選情境 |
| 6 | AI | 依情境處理 |
| 7 | 你 | 說明需求 |
| 8 | AI | 分析 + 方案 |
| 9 | 你 | 確認（只記錄） |
| 10 | 你 | 說「開始交付」 |
| 11 | AI | 列清單 |
| 12 | 你 | 說「確認清單」 |
| 13 | AI | 逐批交付 |
| 14 | 你 | 測試或回報「已更新」 |
| 15 | 對話結束 | AI 更新 SYSTEM-CONCLUSION + SYSTEM-HANDOFF |

### 5.2 專案層對話

| 步驟 | 誰 | 動作 |
|---|---|---|
| 1 | 你 | 上傳 02-CORE-PROJECT.md + 90-{專案}.md |
| 2 | AI | 讀取 + 回報構建編號 + 問哪個專案 |
| 3 | 後續同 5.1 步驟 3 起 | — |

## 七、對話結束綜合機制

| 觸發 | 動作 |
|---|---|
| 使用者說「結束對話」 | 執行綜合 |
| 使用者說「再見 / 之後再說」 | 執行綜合 |
| AI 感知對話自然結束 | 主動建議 |

**執行步驟**：

| 步驟 | 動作 |
|---|---|
| 1 | 回顧本次對話 |
| 2 | 提取新經驗 |
| 3 | 判斷分類（general / system / w / 領域） |
| 4 | 寫入 C-05-learning/ 對應分檔 |
| 5 | 若達閾值 → 建議提升 |
| 6 | 生成「進化報告」 |
| 7 | 待確認後更新 |

## 八、議題表驅動制（D-050~D-057）

**觸發**：每次對話開場時。

| 步驟 | AI 動作 |
|---|---|
| 1 | 讀取對應載體 §一（體系：SYSTEM-CONCLUSION；專案：P-12） |
| 2 | 找出下一個「⏳ 待討論」議題 |
| 3 | 在開場提示「建議下一議題：{N}」 |
| 4 | 允許使用者跳題 |
| 5 | 若跳題，警告依賴關係 |

## 九、新專案建立 SOP 與 Q1~Q6 詢問表

### 9.1 Q1~Q6 詢問表

| 編號 | AI 詢問 | 使用者回答 | AI 後續動作 |
|---|---|---|---|
| **Q1** | 這個專案屬於哪個領域？ | Web App / VBA / 資料分析 / … | 判斷是否已有領域 |
| **Q2** | 是否為新領域？ | 是 / 否 | 否 → 直接開新專案；是 → 建議建 `{X}-*` 6 檔 |
| **Q3** | 是否建立 `{X}-*` 6 檔？ | 確認 / 修改 | 確認 → 產出 6 檔草稿 |
| **Q4** | 6 檔草稿是否可用？ | 回饋 | 依回饋迭代 |
| **Q5** | 新建 Repo 的完整名稱？ | 用戶名/repo名 | 未取得前不准進下一步 |
| **Q6** | 是否更新 `PROJECT_REPOS`？ | 確認 | 更新 `setup-structure.yml` |

### 9.2 新專案完整 SOP

| 步驟 | AI 動作 | 備註 |
|---|---|---|
| 1 | 問「這個專案屬於哪個領域？」（Q1） | 提供 W / V / D / M 等選項。 |
| 2 | 判斷新舊領域（Q2） | 新領域 → 建議 6 檔 |
| 3 | 產出專案骨架（P-01 等）（Q3） | 依領域給 2/4/6 檔 |
| 4 | 依使用者回饋迭代（Q4） | — |
| 5 | **索取「新建的 Repo 完整名稱」**（Q5） | 未取得前不准進入下一步。 |
| 6 | 更新 `setup-structure.yml` 的 `PROJECT_REPOS`（Q6） | — |
| 7 | 提醒使用者在該 Repo 建立 `notify.yml` | 確保 Action 能觸發。 |

### 9.3 6 檔模板

| 1 | {X}-00-startup.md |
| 2 | {X}-01-structure.md |
| 3 | {X}-02-rules.md |
| 4 | {X}-03-sop.md |
| 5 | {X}-04-templates.md |
| 6 | {X}-99-errors-map.md |
