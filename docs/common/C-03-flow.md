## 零、對話 SOP 與狀態機

| 步驟 | 角色 | 動作 |
|---|---|---|
| 1 | AI | 讀取啟動包，回報構建編號。 |
| 2 | 使用者 | 選擇專案。 |
| 3 | AI | 生成編號（防呆 R-004），提示下一議題，停等「繼續」。 |
| 4 | 使用者 | 說「繼續」並提出需求。 |
| 5 | AI | 進入 `STATE_DISCUSS`，提供分析與方案。 |
| 6 | 使用者 | 確認方案。 |
| 7 | AI | **只記錄，不交付**（R-002）。 |
| 8 | 使用者 | 說「開始交付」→ 列清單。 |
| 9 | 使用者 | 說「確認清單」→ 逐批交付。 |

---

## 一、情境決策樹（讀取路由）

| 使用者情境 | AI 讀取目標 | 執行重點 |
|---|---|---|
| 「有問題 / 修 Bug」 | `P-99-errors-map.md` + `C-05-learning` | 跑 5 問自檢、提供診斷與方案。 |
| 「新增功能」 | `P-03-manifest.md` | 評估影響範圍、跑 5 問自檢。 |
| 「改版面」 | `P-06-pagemap.md` | 列出變更前後對照表。 |
| 「新專案」 | 觸發下方 §二 SOP | 領域詢問、索取 Repo。 |
| 「修改體系規則」 | `C-00`, `C-02` | 提出 R-List 或流程修改方案。 |

---

## 二、新專案建立 SOP

| 步驟 | AI 動作 | 備註 |
|---|---|---|
| 1 | 問「這個專案屬於哪個領域？」 | 提供 W / V / D / M 等選項。 |
| 2 | **索取「新建的 Repo 完整名稱」** | 未取得前不准進入下一步。 |
| 3 | 產出專案骨架（P-01 等） | 依領域給 2/4/6 檔。 |
| 4 | 更新 `setup-structure.yml` | 將新專案加入 `PROJECT_REPOS`。 |
| 5 | 提醒使用者在該 Repo 建立 `notify.yml` | 確保 Action 能觸發。 |

## 三、對話結束綜合機制

| 步驟 | 動作 |
|---|---|
| 1 | 回顧對話，提取新經驗。 |
| 2 | 判斷分類（general / system / w）。 |
| 3 | 寫入 `C-05-learning`。 |
| 4 | 更新交接快照（`SYSTEM-HANDOFF`）。 |
