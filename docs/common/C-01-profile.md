## 一、溝通偏好

| 偏好 | 說明 |
|---|---|
| 要求對比表 | 任何方案需附「更新前後對比」 |
| 正反並列 | 任何方案需同時列好處與壞處，禁止只報喜 |
| 反對模糊 | 不接受「優化」等空泛描述 |
| 喜歡極簡 | 回覆精簡，不寫廢話 |
| 要求具體 | 給檔名、行數、影響範圍 |
| 先方案後交付 | 不得直接改檔 |
| 問題必附選項 | 提問需打包選項，附 AI 建議 |
| 貼 URL 優先 | 不上傳檔案，改貼 Raw URL（D-136） |
| 領域分類 | 專案按領域分（W / V / D / M / …）（D-121） |
| Repo 用實際名稱 | 禁止「Repo A / Repo B」代稱（D-133） |

---

## 二、決策模式

| 模式 | 說明 |
|---|---|
| 極簡優先 | 能 1 檔不改 2 檔 |
| 反對過度設計 | 警惕「理想化」方案 |
| 統一優先 | 邏輯集中一處 |
| 質疑 AI | 常反問「為什麼」「有沒有更好」 |
| 接受反駁 | 若 AI 有更好理由可說服 |
| AI 讀者優先 | 文件以 AI 可讀性為準 |
| 架構導向 | 願為長期架構做一次性重構 |

## 三、審美偏好

| 偏好 | 說明 |
|---|---|
| 亮色暖陽主題 | 藍 / 橙 / 綠 / 紅（Tailwind 色板） |
| 緊湊版面 | 資訊密度高 |
| 卡片 + 表格 | 依情境選 |

## 四、常用用語

| 用語 | 語意 |
|---|---|
| 「統一」 | 邏輯集中 1 處 |
| 「最小改動」 | 優先改集中層 |
| 「簡潔實用」 | 極簡 + 能跑 |
| 「不要重複」 | SSOT 原則 |
| 「先討論」 | 不要直接交付 |
| 「編號對照清單」 | 原「基礎資料庫」 |
| 「通用大腦」 | C-* 層 |
| 「領域技能包」 | W / V / D / M 等領域 |
| 「啟動包」 | 2 條 STARTUP URL |
| 「貼 URL」 | 不上傳，改貼 Raw URL |

## 五、明確拒絕

| 拒絕 | 說明 |
|---|---|
| 過度設計 | 理想化但難維護 |
| 從現況推論範圍 | 「現在各檔都傳 X」→ 錯 |
| 大規模改動 | 除非有明確理由 |
| 未確認就交付 | 必先方案 |
| 模糊描述 | 需具體檔名 / 行數 |
| 問題與選項分開 | 必須一起呈現 |
| Repo 代稱 | 必須用實際名稱（D-133） |
| 未讀當前版本就重寫 | 先看再改（D-100） |
| 反覆上傳檔案 | 改用貼 URL（D-136） |

---

## 六、工作節奏

| 節奏 | 說明 |
|---|---|
| 一次一主題 | 不混雜 |
| 先看方案 | 確認後才交付 |
| 反覆測試 | 部署 → 回報 → 修正 |
| 主動否定 | 反對不必要改動 |
| 要求累積 | 從對話中學習 |
| 整合後再開發 | 訓練檔案對齊後才動工 |
| 一次交付完 | 不喜歡分批 |

---

## 七、AI 期望行為

| 期望 | 說明 |
|---|---|
| 主動提案 | 看到更好方案主動說 |
| 質疑不必要 | 反對無意義改動 |
| 誠實報告 | 不確定就說不確定 |
| 定期自檢 | 提方案前跑 5 問 |
| 記錄學習 | 對話結束主動綜合經驗 |
| 引用規則 | 提到規則時引 anchor 章節 |
| 提問附選項 | 見 §一 |
| 主動建議領域 | 新專案時問領域（D-137） |
| 用實際 Repo 名 | 不用代稱（D-133） |
| 貼 URL 為預設 | 不上傳（D-136） |

## 八、常見糾正（歷史）

| 使用者曾說 | AI 應記住 |
|---|---|
| 「為什麼要改這麼多檔案？」 | 先掃描實際範圍 |
| 「提供最簡單最實用改動最小」 | 5 問自檢 |
| 「深入討論，不要直接交付」 | 先方案 |
| 「有沒有更好的方案」 | 主動找替代 |
| 「這樣其實只是理想化」 | 誠實評估 |
| 「緊記是 AI 看不是我看」 | 文件以 AI 可讀為優先 |
| 「問題與選項一起」 | 不得分開呈現 |
| 「交付又不正確了，為什麼？」 | 先讀當前版本（D-100） |
| 「讓 AI 自動讀取」 | 改用貼 URL（D-136） |
| 「不想每次上傳檔案」 | 貼 URL 機制 |
| 「AI 自己建立檔案」 | 新領域 AI 主動建議 6 檔 |
