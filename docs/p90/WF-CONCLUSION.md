## 二、設計結論

### 2.1 編號系統與 API 統一（B34-4 定案）
1. **統一端點**：廢棄所有獨立 CRUD 端點，統一由 `POST /api/entity-create` 處理。
2. **編號生成**：由前端遍歷現有資料取得最大編號 +1。

### 2.2 專案重組與體系對齊（B34-5 定案）
1. **紀錄檔重組**：專案技術文件保留 `P-*`，紀錄檔全面轉為 `WF-*`。
2. **領域資料抽離**：通用 Web App 規則已抽至體系 `W-00 ~ W-07`。

### 2.3 全新 V2 架構（D-175 定案）
1. **SPA + Hash 路由**：放棄舊版多 HTML 架構，改為單一 `index.html` 搭配 `engine/router.js`。
2. **資料層拆分**：將舊版巨型 `db.js` 拆分為 `db/read.js` 與 `db/write.js`。
3. **後端整合**：將舊版 11 個 API 檔整合為 5 檔，並移至 `functions/api/` 目錄。

### 2.4 UI 統一排版引擎（D-176 定案）
建立 `renderPageLayout` 引擎（位於 `ui/layout.js`），強制所有頁面遵循「標題 → 統計卡 → 控制列 → 列表」的順序。

### 2.5 全面引擎化與防破版（本次定案）
1. **表格引擎復活**：`ui/table.js` 重寫，全面恢復 V1 的表頭三態排序、表頭下拉篩選與欄位顯示設定。
2. **消除手寫表格**：`admin.js`、`annual-report.js` 等頁面的手寫 `<table>` 全面改為呼叫 `renderTable`，解決排序與破版問題。
3. **防破版約束**：`ui/layout.js` 與 `ui/table.js` 加入 `min-width: 0` 與 `overflow-x: hidden`，徹底解決手機端版面撐破問題。

### 2.6 幽靈依賴清理（本次定案）
1. **拔除 V1 遺毒**：全面移除 `shared/`、`entity/`、`ui/entity-modal.js` 的引用。
2. **原生引擎組合**：如 `settings.js` 的成員與銀行列表，改用 `listen` + `renderTable` 現場組裝；`portfolio.js` 改用 `ui/form.js` 建立彈窗。
