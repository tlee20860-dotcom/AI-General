**用途**: 記錄本專案歷史中被否決的方案與原因，避免後續 AI 或開發者重複提出已被否決的設計。

## 二、被否決方案清單

| 編號 | 方案主題 | 否決原因 | 替代方案 | 決策來源 |
|---|---|---|---|---|
| RJ-92-001 | 使用 React 或 Vue 框架 | 專案初期規模較小，引入框架會增加建置複雜度與學習成本；且工廠現場對載入速度敏感，框架 bundle 過大。 | 採用純 Vanilla JS + ES Module，並以 `order-view.js` 單一渲染引擎解決重複程式碼問題。 | D-92-001、D-92-005 |
| RJ-92-002 | 使用 `.env` 存放 Firebase 金鑰 | 使用者初期無電腦環境可建立隱藏檔；且前端 `apiKey` 本身為公開性質，隱藏無實質安全收益。 | 建立 `src/config/firebase-keys.js` 直接寫入配置，搭配 Firestore 安全規則作為真正的存取控制。 | D-92-002 |
| RJ-92-003 | 列表頁保留行內編輯與下拉選單 | 資料在列表頁被修改後，與彈窗編輯不同步；且工廠現場容易誤觸下拉選單，造成狀態錯亂。 | 列表頁純粹展示，所有修改統一由「點擊單號開啟彈窗」進行；僅看板保留狀態推進按鈕。 | D-92-021、W-03 R12 |
| RJ-92-004 | 使用 HTML5 原生 `draggable="true"` 實作拖曳排序 | 電腦端正常，但手機端手指按住時會觸發頁面滾動，完全無法拖曳。 | 引入 `SortableJS`，並設定 `forceFallback: true` 與 `fallbackTolerance: 3`，強制使用模擬 DOM 拖曳。 | W-07 §二、L-051 |
| RJ-92-005 | 使用 `setDocument` 全量覆蓋 `settings/main` | 會導致未被包含在該次表單中的欄位（如區域、模板、物料）被全部洗掉。 | 全面改用 `updateDocument` 進行局部更新，且只傳入當下修改的欄位。 | W-07 §二、P-Architecture §一.5 |
| RJ-92-006 | 使用局部替換（PARTIAL_REPLACE）交付檔案 | 局部替換的 `OLD` 字串匹配失敗率高，且容易漏寫 EOF，導致前端控制台拒絕發布。 | 體系 SV14 全面單軌制，僅使用完整檔（FULL_FILE）交付。 | 體系 R-010、F-007（SV14） |
| RJ-92-007 | 使用增量（APPEND_ONLY）交付累積型紀錄檔 | 增量標記 `[APPEND]` 與局部替換標記容易混淆；且前端需額外處理舊 EOF 切除，增加出錯點。 | 體系 SV14 全面單軌制，累積型紀錄檔亦使用完整檔交付。 | 體系 F-007（SV14） |
| RJ-92-008 | 將動態進度（如檔案清單、版本號）塞入靜態規則檔 | 每次更新進度就觸發規則版本熱更新，造成 FSM 死鎖與認知溢出。 | 動態進度與靜態規則物理隔離；全庫索引與進度只能存在 SP 或生成物中。 | 體系 L-032 |
| RJ-92-009 | 使用單一 `lastSyncTime` 追蹤 Excel 自動同步 | 若一次放入多個不同檔名的 Excel，只有最新的會被匯入，其他檔案漏接。 | 改用 `localStorage` 記錄「每個檔名」的修改時間，獨立比對與追蹤每個檔案。 | D-92-025、W-06 §一.2 |
| RJ-92-010 | 假設 Excel 表頭固定在第一行 | 公司系統導出的 Excel 前幾行有公司名稱、地址，表頭不在第一行，導致匯入失敗。 | 升級 `parser.js`，掃描前 20 行尋找包含「單號」、「登錄」等關鍵字的行作為表頭。 | D-92-026、W-07 §三 |
| RJ-92-011 | 手動維護工單類別清單 | 匯入未知類別時，系統雖能存檔，但類別選單沒有更新，導致下拉選單缺失。 | 匯入時若發現新類別，自動補齊至 `settings.categories`，並在類別管理頁面提供「一鍵同步」按鈕。 | D-92-027、W-07 §三 |
| RJ-92-012 | 以「現在各檔都傳 X」推論作用範圍 | 這是常見的 AI 推理錯誤，會把區域性的做法誤推為全域規則。 | 一律以實體檔與明文規則為準，禁止從現況反推規則。 | 體系 L-030、U-00 §五 |
| RJ-92-013 | 在列表頁使用 `addEventListener` 綁定按鈕 | SPA 路由切換重繪後，監聽器失效，導致按鈕點不到。 | 改用全域事件委派，綁定在 `document` 上，透過 `data-action` 辨識目標。 | D-92-005、W-03 R08 |
| RJ-92-014 | 先呼叫 `createIcons()` 再綁定事件 | 圖示初始化若報錯中斷，後續綁定事件與渲染資料的程式碼被跳過，按鈕完全失效。 | 先綁定事件（或使用事件委派），最後才呼叫 `createIcons()`。 | W-03 R09、W-07 §二 |
| RJ-92-015 | 使用前端明文比對作為最終認證方案 | 帳密以明文形式儲存於 `settings.users`，且前端可讀取，安全性不足。 | 目前作為測試期過渡方案；上線前需替換為 Firebase Auth。 | D-92-002 備註、WF-HANDOFF §三 |
