# WF-CONCLUSION (p92 UPGRADE-WO)

**最後更新時間**: 2026-10-31

## 一、專案架構決策紀錄

| 編號 | 決策主題 | 決策內容 | 原因與備註 |
|---|---|---|---|
| D-92-001 | 前端架構模式 | 採用 Mode B（Vite + Vanilla JS + Tailwind CSS）。 | 專案包含複雜的 Excel 解析、PDF 匯出與多視圖切換，需要現代化構建工具與模組化管理。 |
| D-92-002 | Firebase 金鑰存放 | 建立 `src/config/firebase-keys.js` 直接寫入配置，豁免 `.env` 機制。 | 因使用者初期無電腦環境可建立隱藏檔，且前端 `apiKey` 本身為公開性質。 |
| D-92-003 | 狀態修改機制 | 表格與卡片直接使用 `<select>` 下拉選單修改生產進度。 | 取代原本的「流轉」按鈕，減少操作層級，選擇後即時存檔，符合工廠直覺。 |
| D-92-004 | Excel 防覆寫機制 | 在匯入時比對 ID，存在則僅更新 Excel 欄位（金額、類別等），保留狀態與交期。 | 嚴格遵守「防覆寫」需求，避免重複匯入導致現場工單進度被重設。 |
| D-92-005 | 統一渲染引擎 | 全站（工單、總表、總狀態、類別、銷售員）統一由 `src/ui/order-view.js` 渲染。 | 徹底消滅重複程式碼，並採用全域事件委派，解決 SPA 切換導致按鈕失效的問題。 |
| D-92-006 | 動態視圖配置 | 在系統設定中新增「視圖配置」，由使用者勾選各頁面要顯示的動態欄位。 | 實現完全數據驅動，未來換 Excel 或新增欄位完全不需要修改程式碼。 |
| D-92-007 | PWA 導入 | 加入 `manifest.json` 與 `sw.js`，支援手機加到主畫面。 | 提升行動端體驗，使其具備接近原生 App 的載入速度與全螢幕體驗。 |
| D-92-008 | 部署流程變更 | GitHub Actions 改為手動觸發（`workflow_dispatch`）。 | 讓使用者能控制發布時機，避免測試階段過度頻繁的部署。 |
| D-92-009 | 管理員資料總管 | 新增 `admin-data` 頁面（僅 Admin 可見），提供一鍵清空與徹底刪除功能。 | 方便管理員清理測試或錯誤資料（如星號垃圾工單）。 |
| D-92-010 | 對照表編輯優化 | 將連續的 `window.prompt` 改為單一表單彈窗，可同時編輯名稱與別名。 | 提升使用者體驗，避免多次彈窗被瀏覽器攔截或造成操作中斷。 |
| D-92-011 | 行內編輯與動態選單 | 表格與卡片支援 `isEditable` 欄位行內編輯，狀態改為上下步按鈕，並可透過 ⚙️ 開啟雙清單調整製程。 | 大幅降低操作層級，讓工廠現場人員可以像操作 Excel 一樣直覺地修改資料與推進進度。 |
| D-92-012 | Modal 三層架構重構 | 將 `modal.js` 重構為「標題固定、內容滾動、底部按鈕固定」的三層架構。 | 徹底解決手機端內容過長時，底部按鈕被推出畫面或無法滑動的破版問題。 |
| D-92-013 | 製程模板與類別綁定 | 新增「製程模板」管理，可設定對應的工單類別（如 GF、LS），匯入時自動套用。 | 滿足不同產品線有不同生產 SOP 的需求，同時保留手動微調的彈性。 |
| D-92-014 | 全域設定即時監聽 | 在 `main.js` 加入 `listenDocument('settings')`，變更時派發 `settings-updated` 事件通知全站刷新。 | 解決過去在設定頁修改工序後，必須切換頁面才會生效的快取延遲問題。 |
| D-92-015 | 全域搜尋機制 | 移除表格行內篩選列，改為右上角單一全域搜尋框。 | 簡化 UI 視覺，並提供跨欄位的快速搜尋體驗。 |
| D-92-016 | 引入區域管理與多對多綁定 | 新增「區域」概念，將工序綁定至區域，並支援一個工序屬於多個區域。區域可設定「負責類別」以過濾顯示的工單。 | 滿足工廠多機台、多產線的顯示需求，並透過類別過濾避免工單跨區亂跑。 |
| D-92-017 | 視圖權責與資料流重構 | 管理總表專職「設定交期與切換生產流程」；進度表專職「按類別分頁、顯示工序與上下步按鈕」；總狀態改以區域為樞紐；銷售員視圖支援按工序分區塊並顯示所在區域。 | 重新梳理各頁面職責，降低使用者認知負擔，並統一以「類別」作為進度表的主分類。 |
| D-92-018 | 四角色權限矩陣 | 帳號區分為 `admin`（全權）、`worker`（僅看區域，可推進程）、`sales`（僅看銷售員，唯讀）、`viewer`（全站唯讀）。實作路由守衛、選單過濾與渲染層 `allowStatusChange` 控制。 | 滿足生產現場與業務單位的權限隔離需求，防止越權修改。 |
| D-92-019 | SortableJS 手機拖曳優化 | 移除上下箭頭按鈕，引入 `SortableJS` 並設定 `forceFallback: true`，解決原生 HTML5 拖曳在手機端失效與滾動衝突的問題。 | 提供跨裝置一致的直覺拖曳體驗。 |
| D-92-020 | 本機 Excel 自動同步 | 使用 `File System Access API` 綁定本機資料夾，結合 `setInterval` 與 `focus` 事件輪詢檢查，實現存檔後網頁自動匯入。 | 減少手動匯入的操作步驟，此功能僅限支援 API 的桌機版 Chrome/Edge。 |
| D-92-021 | 原生推播通知 | 利用 `Notification API` 與 `listenCollection`，當工單狀態更新時，比對角色權限並發送背景通知。 | 即時通知相關的生產員與銷售員，避免漏單。 |
| D-92-022 | 區域狀態切換 | 新增「區域狀態」字典管理（如正常、壞機），並允許生產員在區域卡片上快速切換。 | 讓管理者與現場人員一眼看出產線當下的運作狀況。 |
