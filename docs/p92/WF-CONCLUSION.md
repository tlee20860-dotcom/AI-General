# WF-CONCLUSION (p92 UPGRADE-WO)

**最後更新時間**: 2026-11-09

## 一、專案架構決策紀錄

| 編號 | 決策主題 | 決策內容 | 原因與備註 |
|---|---|---|---|
| D-92-001 | 前端架構模式 | 採用 Mode B（Vite + Vanilla JS + Tailwind CSS）。 | 專案包含複雜的 Excel 解析、PDF 匯出與多視圖切換，需要現代化構建工具與模組化管理。 |
| D-92-002 | Firebase 金鑰存放 | 建立 `src/config/firebase-keys.js` 直接寫入配置，豁免 `.env` 機制。 | 因使用者初期無電腦環境可建立隱藏檔，且前端 `apiKey` 本身為公開性質。 |
| D-92-003 | 狀態修改機制 | 表格與卡片直接使用 `<select>` 下拉選單修改生產進度。 | 取代原本的「流轉」按鈕，減少操作層級，選擇後即時存檔，符合工廠直覺。 |
| D-92-004 | Excel 防覆寫機制 | 在匯入時比對 ID，存在則僅更新 Excel 欄位（金額、類別等），保留狀態與交期。 | 嚴格遵守「防覆寫」需求，避免重複匯入導致現場工單進度被重設。 |
| D-92-005 | 統一渲染引擎 | 全站（工單、總表、總狀態、類別、銷售員）統一由 `src/ui/order-view.js` 渲染。 | 徹底消滅重複程式碼，並採用全域事件委派，解決 SPA 切換導致按鈕失效的問題。 |
| D-92-006 | 動態視圖配置 | 在系統設定中新增「視圖配置」，由使用者勾選各頁面要顯示的動態欄位。 | 實現完全數據驅動，未來換 Excel 或新增欄位完全不需要修改程式碼。 |
| D-92-007 | PWA 導入 | 加入 `manifest.json` 與 `sw.js`，支援手機加到主畫面。 | 提升行動端體驗，使其具備接近原生 App 的載入速度與全螢幕體驗。 |
| D-92-008 | 部署流程變更 | GitHub Actions 改為手動觸發（`workflow_dispatch`）。 | 讓使用者能控制發布時機，避免測試階段過度頻繁的部署。 |
| D-92-009 | 管理員資料總管 | 新增 `admin-data` 頁面（僅 Admin 可見），提供一鍵清空與徹底刪除功能。 | 方便管理員清理測試或錯誤資料（如星號垃圾工單）。 |
| D-92-010 | 對照表編輯優化 | 將連續的 `window.prompt` 改為單一表單彈窗，可同時編輯名稱與別名。 | 提升使用者體驗，避免多次彈窗被瀏覽器攔截或造成操作中斷。 |
| D-92-011 | 行內編輯與動態選單 | 表格與卡片支援 `isEditable` 欄位行內編輯，狀態改為上下步按鈕，並可透過 ⚙️ 開啟雙清單調整製程。 | 大幅降低操作層級，讓工廠現場人員可以像操作 Excel 一樣直覺地修改資料與推進進度。 |
| D-92-012 | Modal 三層架構重構 | 將 `modal.js` 重構為「標題固定、內容滾動、底部按鈕固定」的三層架構。 | 徹底解決手機端內容過長時，底部按鈕被推出畫面或無法滑動的破版問題。 |
| D-92-013 | 製程模板與類別綁定 | 新增「製程模板」管理，可設定對應的工單類別（如 GF、LS），匯入時自動套用。 | 滿足不同產品線有不同生產 SOP 的需求，同時保留手動微調的彈性。 |
| D-92-014 | 全域設定即時監聽 | 在 `main.js` 加入 `listenDocument('settings')`，變更時派發 `settings-updated` 事件通知全站刷新。 | 解決過去在設定頁修改工序後，必須切換頁面才會生效的快取延遲問題。 |
| D-92-015 | 全域搜尋機制 | 移除表格行內篩選列，改為右上角單一全域搜尋框。 | 簡化 UI 視覺，並提供跨欄位的快速搜尋體驗。 |
| D-92-016 | 資料錄入頁面與表單引擎分離 | 新增 `data-entry.js` 與 `order-editor.js`，並導入 `formula-engine.js`。 | 提供獨立的打單頁面，並將公式計算邏輯從 UI 抽離，確保資料輸入時能即時且正確地計算（如工單銀碼）。 |
| D-92-017 | 差異核對機制與警示 | 導入 `data-diff.js`，在 Excel 匯入時比對「手動工單」與 Excel 的差異。 | 嚴格遵守「手動輸入優先」原則。若金額等指定欄位不符，保留手動輸入值，並在介面標示紅色驚嘆號，直到使用者手動修改為止。 |
| D-92-018 | 設定頁面拆分 | 將原本的「系統設定」拆分為「生產設定」與「表單設定」兩個獨立入口。 | 降低單一頁面的認知負荷，讓工廠流程設定與介面/資料欄位設定各自獨立，方便管理。 |
| D-92-019 | Excel 匯出支援自訂欄位與全備份 | 匯出時可自由勾選欄位，並增加一張包含所有資料庫欄位的「全部工單」Sheet。 | 滿足日常匯出特定欄位的需求，同時提供完整的資料庫備份能力，避免隱藏欄位遺失。 |
| D-92-020 | 匯入規則升級（支援備份還原） | 升級 `parser.js` 解析核心欄位。舊單防覆寫保留狀態；新單則讀取 Excel 的狀態與製程。 | 確保「匯出再匯入」時能完美還原工單狀態與製程路線，同時不影響日常更新舊單進度的安全性。 |
| D-92-021 | 單一編輯入口原則 | 拔除列表頁的行內編輯與下拉選單，統一由「點擊單號開啟彈窗」進行修改。僅看板保留狀態推進。 | 避免資料在列表頁被修改導致與彈窗不同步，減少誤觸，並收斂系統操作邏輯。 |
| D-92-022 | 四大設定中心重構 | 將設定拆分為「物料管理」、「工單管理」、「生產管理」與「系統管理」四個獨立頁面。 | 解決單一設定檔過於龐大的問題，並符合不同職能（生管、會計、IT）的分工需求。 |
| D-92-023 | 新增物料主檔與工單明細 | 建立物料主檔（可自訂欄位），並在工單彈窗中可加入物料明細。物料下拉選單會依類別過濾。 | 讓系統能記錄每張工單的實際用料，且透過類別過濾避免選錯物料。 |
| D-92-024 | 新增外發供應商主檔 | 建立供應商主檔（可自訂聯絡資訊欄位），工單可選擇外發廠商。 | 滿足工廠外發需求，並統一管理外發廠商資訊。 |
| D-92-025 | 多檔案自動同步 | 自動同步改為使用 `localStorage` 記錄每個檔案的修改時間，支援多個不同檔名的 Excel 獨立追蹤。 | 解決「有限公司」與「無限公司」兩份報表無法同時自動同步的問題。 |
| D-92-026 | 自動偵測表頭 | 升級 `parser.js`，掃描前 20 行尋找包含「單號」、「登錄」等關鍵字的行作為表頭。 | 解決公司系統導出的 Excel 前幾行有標題、地址，導致匯入失敗的問題。 |
| D-92-027 | 類別自動同步機制 | 匯入時若發現未知類別，自動補齊至 `settings.categories`，並在類別管理頁面加入「一鍵同步」按鈕。 | 避免手動維護類別清單的困擾，並確保下拉選單的完整性。 |
| D-92-028 | 開單日期以 Excel 為準 | 將 `uploadDate` 更名為「開單日期」並設為唯讀。匯入時，即使是舊單也以 Excel 內的日期覆寫。 | 符合使用者「手動新增先抓今天，但最後以 Excel 日期為準」的業務邏輯。 |
| D-92-029 | 全域搜尋支援物料 | `src/domain/global-search.js` 的 `flattenOrder` 將 `order.materials` 陣列中的 `name` 與 `note` 展平為 `materials.{idx}.name` / `materials.{idx}.note`，納入關鍵字搜索範圍；搜索結果顯示欄位維持既有配置不變。 | 滿足「在搜索頁輸入大約物料名稱即可搜出相關工單」的需求。僅改 1 檔 1 函式，最小改動；不觸及顯示層，避免連帶影響 `order-view.js` 與視圖配置。 |
| D-92-030 | 紀錄檔命名全面 WF 化 | 專案紀錄與技術檔全面廢除 `P-*` 命名，改為 `WF-*`。既有技術檔更名：`P-Architecture.md` ➜ `WF-ARCH.md`、`P-Data.md` ➜ `WF-DATA.md`、`P-Dev-SOP.md` ➜ `WF-SOP.md`；新增缺失的 4 寶：`WF-EVOLUTION.md`、`WF-REJECTED.md`、`WF-DEBT.md`、`WF-ARCHIVE.md`。 | 對齊 SV14 七寶對稱架構（A-00 §4.4、§5.5）與詞 101。避免 `P-*` 與 `WF-*` 並存造成認知分裂；舊路徑由控制台手動刪除。 |
| D-92-031 | 本次對話跳過 SV14 結束 SOP | 原 SV13 結束對話 SOP 已中止；本次交付聚焦於紀錄檔遷移，不重新觸發 `E_HANDOFF`。遷移完成後由 Ken 決定是否另開新對話執行 SV14 結束 SOP。 | 避免在同一對話中混用兩套結束 SOP；SV14 的 `STATE_SEAL` 與退出重置需在乾淨的會話狀態下執行，降低認知溢出風險。 |
