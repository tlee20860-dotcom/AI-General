### 2.55 WF 大一統與偽 EOF 提取法（SV14 定案）
1. **偽 EOF 提取法**：修改 `F-007`，局部替換不再要求 `NEW` 區塊包含完整檔案尾端，只需在補丁下方提供一個獨立的 EOF 區塊。前端自動切除舊 EOF 並縫合新 EOF。大幅降低 Token 消耗與匹配失敗率。同時禁止 `.json` 使用局部替換（因無註解語法）。
2. **專案命名大一統**：全面廢除專案 `P-*` 與數字前綴（如 `90-P-Data.md`），統一改為 `WF-*`（如 `WF-DATA.md`）。`setup-structure.yml` 與相關正則同步更新，杜絕命名混亂。
3. **7 寶對稱架構**：專案結束對話 SOP 全面對齊體系端，強制維護 7 個核心檔案（`WF-HANDOFF`、`WF-PROGRESS`、`WF-CONCLUSION`、`WF-EVOLUTION`、`WF-REJECTED`、`WF-DEBT`、`WF-ARCHIVE`）。
4. **歷史自動彙整**：`24-HISTORY.md` 打包時，除了體系歷史，還會自動掃描並合併所有專案的 `WF-EVOLUTION.md`。
5. **前端重命名刪除功能**：`index.html` 新增「準備刪除的舊路徑」輸入框，搭配 `F-010` 規則，AI 交付時提供獨立的舊路徑區塊供一鍵複製。前端發布新檔後，會自動呼叫 API 刪除舊檔，實現無痛改名。
6. **結構性錯誤物理阻斷**：新版前端在 `PARTIAL_REPLACE` 模式下，若找不到 `OLD` 字串，將隱藏「強制發布」按鈕，防止毀損源碼（但在 `FULL_FILE` 模式下仍保留按鈕以防誤攔截）。
