## 二、設計結論

### 2.25 體系微核心化 v1.5（006 定案）

### 2.26 三 AI 模式與審查包機制（007 定案）
1. **三 AI 模式**：體系開發與結構師、挑戰方案對抗者、合規審判者；對抗者與審判者為外部角色，不進 FSM。
2. **CHK 機制**：新增 `docs/review/` 四檔，定義 15 條可核對項目（CHK-E-001~015）。
3. **特徵化與例外**：CHK-E 期望全面特徵化；REVIEW-FORMAT 新增「特徵搜尋類」與「定點檢查類」，不強制給前中後。
4. **打包自動化**：Action 新增 Step 6.5，缺任一源檔即失敗，不產出半套 CHK.md。
5. **防堵敷衍**：引入 FMT-09，判定必須基於期望特徵，拿無關行號湊數即 FAIL。

### 2.27 體系進化史與 R-019（008 定案）
1. **進化史獨立**：新增 `SYSTEM-EVOLUTION.md`（第七檔），記錄體系形態的架構級變化、載體搬遷、制度誕生；只記形態，不記決策明細與任務進度。
2. **時間軸總覽**：§零點五 以表格呈現各段起迄、跨度、史料狀態；無證據日標「無直接證據，推測…」。
3. **衝突表**：§八 累積 33 項史料衝突，各段只記該期形態，不跨期混用。
4. **R-019 結構變更提示**：交付涉及拆檔、增檔、刪檔、引入新模式／角色、FSM 或分層大變時，必須列結構變更清單並提示記入進化史；AI 不得自行寫入。

### 2.28 區模型與權限階層（009 定案）
1. **區模型**：四檔進體系，＋SP 進體系核心，＋領域包進領域，＋專案包進專案區，＋CHK 進審核區。單區獨佔，須退出才能換區。
2. **權限與角色**：初創者（Ken）＞體系開發者（全權）＞領域開發者（領域包須 Ken 同意）。核心區切換角色須輸入 `[授權切換：角色]`。
3. **上傳判定**：四檔全域熱更新。異區上傳提示退出。混合包（合法＋非法）原子性阻擋。
4. **歷史歸檔**：新增 `SYSTEM-ARCHIVE.md`（APPEND_ONLY）。累積型檔案（REJECTED／DEBT／R-04 等）達門檻後，舊資料搬至 ARCHIVE，正文節尾留一行指標。
5. **F-005 修正**：改為「內文不得重複 Version 或 Writer（代碼內容除外）」；採漸進式收斂，改檔時順手刪檔頭三行。
6. **歷史包與時間戳**：新增 `HISTORY.md` 歷史包（含 EVOLUTION／REJECTED／DEBT／R-04）。合成包生成時間移至第一行。

### 2.29 密語安全機制與紀錄對齊（009 定案）
1. **交付密語**：AI 不得再憑自由心證交付。必須收到 Ken 專屬密語 `方案已定案可交付` 才能輸出檔案。
2. **特權密語**：新增 4 個防呆鎖（破壞性操作、全域批次、強制中止、跨區操作），全數寫入 `R-00` R-020~R-023。
3. **排版規範**：提供密語時，必須獨立成行並用 Code Block 包裹，禁止列入 A/B/C 選項。
4. **目錄對齊**：所有專案紀錄（`WF-*`）統一放至 `docs/records/`，與體系架構一致。
5. **R-05 補齊**：同步將 R-020~R-023 與密語事件映射至 DSL。

### 2.30 防呆物理化與死模板（009 定案）
1. **FSM 鎖死**：`T01` 轉移的 Guard 加入 `received_confirm_word == true`。未收到密語，系統不允許輸出檔案。
2. **F-001 死模板**：將交付標頭改為不可變的 Markdown 區塊，禁止 AI 使用表格或自由排版。
3. **根源解決**：領域層 AI 的認知負荷高，純文字規則易被忽略，必須以「物理模具」與「密語鎖」進行約束。

### 2.31 Webapp 重構路線（010 定案）
1. **廢棄 V2（41 檔）**：因其雙軌並存（`app-pages` 與 `pages` 衝突）且底層依賴斷裂，修復成本過高。
2. **保留 V1（129 檔）**：舊版已補回 `[[path]].js` 並恢復正常，功能 100% 完整。
3. **重構方向**：傾向在舊版基礎上進行「漸進式瘦身」或「合併為 5~7 核心檔」，保留功能並降低 AI 交付負擔。

### 2.32 體系角色矩陣扁平化（011 定案）
1. **現狀問題**：現行 Meta/Web 分角色機制，要求使用者切換身份才能寫程式碼，嚴重違反使用者（UP）的「極簡」與「一次處理一主題」偏好。
2. **定案方向**：廢除分身矩陣、5-Core、沙盒（MetaSandbox/FastDev）與隔離鎖（G1/G2/G3）。全面回歸單一全能型態。

### 2.33 單一全能型態與嚴格防呆（011 定案）
1. **唯一身份**：體系內僅保留「系統架構師（System Architect）」，不再區分領域分身。
2. **包驅動邏輯**：做什麼事取決於上傳了什麼包（四檔＋SP＝體系；專案包＝業務），不需打 `[身份: xxx]`。
3. **嚴格無省略**：`F-008` 新增規定，交付完整檔時 MUST 逐字輸出，禁止出現「略」、「保留原樣」等詞彙。
4. **單檔交付限制**：`R-010` 新增規定，一回覆僅限交付 1 檔，強制多檔任務必須分批交付。
5. **自動備份**：新增 `daily-backup.yml`，每天 HKT 早上 6 點自動打 Tag 備份。

### 2.34 統一大腦與生成物物理隔離（012 定案）
1. **源檔扁平化**：專案紀錄（`WF-*`）與技術檔（`P-*`）全部集中在 `AI-General/docs/p{專案編號}/`，不再散落各專案倉庫。
2. **生成物集中**：所有合成物（`IP`/`AP`/`RP`/`UP`/`WP`/`SP-Sys`/`SP-90`/`90-P`/`90-Code` 等）統一由腳本生成並只推送到 `AI-Packages`。嚴禁回寫源檔倉庫，徹底消滅 Commit 衝突。
3. **雙狀態分離**：廢除單一 `SP.md`。體系進度獨立為 `SP-Sys.md`；專案進度獨立為 `SP-{專案編號}.md`，避免改 Code 時被體系技術債干擾。
4. **源檔自動備份**：新增 `backup.yml`，每日定時為源檔倉庫建立 Git Tag 快照，防止手貼覆蓋導致資料遺失。

### 2.35 重構防呆機制（012 定案）
1. **重構地圖**：`R-024` 規定，AI 在執行重構、重組、合併、拆分等任務時，**必須先交付 `Refactor-Map.md`**，列出舊檔案、新檔案、處置動作與影響範圍。
2. **確認後動工**：必須經 Ken 確認地圖無誤，方可輸出程式碼。
3. **取代關係標記**：`F-001` 新增 `♻️ 取代關係` 欄位，單檔替換直接填寫，大範圍重構填寫「詳見 Refactor-Map」。

### 2.36 控制台備份整合與完整結構複製（012 定案）
1. **控制台 GUI**：在 `index.html` 新增「倉庫備份管理」卡片，可勾選要備份的倉庫並指定目標備份倉庫。
2. **完整結構複製**：`copy-backup.yml` 使用 `cp -a` 確保目錄結構完全保留，並存放到 `backup-YYYYMMDD-HHMM` 資料夾中。

### 2.37 雙階段密語與防呆排版（013 定案）
1. **雙階段密語**：將原單一密語拆分為「方案已落實」（允許輸出清單）與「清單已確定開始交付」（允許輸出檔案），徹底解決交付流程模糊與提前輸出的問題。
2. **R-019 獨立提問**：重大結構變更提示必須獨立於交付清單之外，優先詢問 Ken，待決策後方可輸出清單。
3. **R-014 排版規範**：提問與選項集中於回覆末尾；提供密語時必須獨立成行並用 Code Block 包裹，禁止作為選項名稱或與選項混寫。

### 2.38 合成物認知與 F-005 例外（013 定案）
1. **專案合成物定位**：AI 收到的專案程式碼為合成物。AI 必須從合成物中定位目標源碼進行修改，交付單一完整檔，不得假設使用者是單檔上傳。
2. **F-005 語言例外**：為避免 JSON 語法崩潰與 JS 缺乏註解，`.json` 豁免 EOF，`.js` 與 `.css` 使用該語言註解包裹 EOF。若遇規則衝突，須提出架構溢出宣告，不得自行發明例外。

### 2.39 通用編號與專案決策前綴（013 定案）
1. **通用編號**：開場僅載入四檔時，對話編號預設為 `general-{YYYYMMDD}-{序號}`，表示處於尚未確認任務性質的純討論狀態。
2. **專案決策編號**：若在專案區（無 `SYSTEM-CONCLUSION.md`），決策編號 MUST 採用 `D-{專案編號}-{序號}` 格式（如 `D-90-001`），並寫入該專案的 `WF-CONCLUSION.md`。
3. **通用決策紀錄**：新增 `GENERAL-CONCLUSION.md`（打包為 `04-GC.md`），記錄 `G-{序號}`，專供純討論階段使用。

### 2.40 體系甦醒與版本發布優化（013 定案）
1. **對話甦醒機制**：擴充 FSM `T07b` 轉移的 `from` 條件為 `[WAIT_CONFIRM, TERMINATED]`。當對話終止後收到新任務，會自動退回 `DISCUSS` 狀態並讀取 `STATE_SEAL` 恢復記憶。
2. **體系版本發布**：不新增獨立檔案。改為在 `SYSTEM-HANDOFF.md` 檔頭加入 `version: SVXX` 欄位，作為每次對話結束的版本發布標籤（覆蓋發布）。
3. **極簡化落實**：拒絕為了解決單一問題而過度新增檔案與事件，優先複用現有機制。

### 2.41 通用決策更新與選項限制（013 定案）
1. **通用決策結案**：將 `GENERAL-CONCLUSION.md` 納入 `A-00 §5.6` 的 `affected` 演算與結束 SOP 更新清單。只要對話前綴為 `general` 且有決策，結束時就必須更新。
2. **嚴格限制選項輸出**：修改 `R-014`，規定只有 `STATE_DISCUSS` 可提供 A/B/C/D 選項；進入 `DELIVER`、`EXECUTE` 或 `WAIT_CONFIRM` 後，MUST NOT 輸出任何選項。任何密語與提示詞一律使用 Code Block 包裹。

### 2.42 會話鎖與隔離區防呆（013 定案）
1. **建立會話鎖（Session Lock）**：開場載入四檔後，強制鎖定當下的 `V` 欄位與版本號。
2. **物理隔離區（Quarantine Zone）**：若對話中途收到任何體系檔案（IP/AP/RP/UP/SP-Sys），AI MUST 輸出警告並將其移入隔離區，拒絕載入新內容。
3. **徹底封殺熱更新**：廢除 `E_HOT_UPDATE` 與 `E_STALE_PACKAGE`，防止中途換檔導致 AI 精神錯亂與規則衝突。
