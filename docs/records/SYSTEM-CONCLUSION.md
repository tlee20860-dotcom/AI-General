### 2.47 體系終極重構與前端物理防呆建立（SV08 定案）
1. **FSM 降維與兩階段密語**：廢除 YAML 矩陣，改為人話流程表。導入「方案已落實...」與「交付清單已確認...」兩階段密語。杜絕 LLM 認知溢出與偷跑。
2. **編號無狀態化**：廢除帶日期編號，改用純流水號（由 HANDOFF 自動推算），解決 AI 算數出錯。
3. **前端受控全量覆寫**：廢除原生 Patch。網頁控制台下載原檔，在記憶體中替換/追加，更新 EOF 後推回。若不匹配則拒絕發布，確保源檔零污染。
4. **配置驅動與動態載入**：建立 `validate-config.json` 與 `forbidden_words.txt`。網頁前端動態抓取，不再寫死字典與白名單。後端腳本導入 `zhconv` 精準抓錯。
5. **極簡 CoT 自檢**：拔除長篇 K-001 自證，AI 交付僅需一行 `[內部自檢...]`。
6. **LLM 專屬抗幻覺審查**：R-016 升級，對抗審查須直指 LLM 四大危機。

### 2.48 局部替換、生命週期與控制台防呆升級（SV09 定案）
1. **新增局部替換模式（PARTIAL_REPLACE）**：允許 AI 針對 ≤10 行的修改提供精準 `OLD/NEW` 區塊，節省 Token 並由前端控制台進行記憶體替換。若匹配失敗，AI 必須退回完整檔。
2. **端到端發布生命週期**：明確定義從「AI 輸出」到「控制台檢查」再到「Action 打包」的標準迴圈，並加入寫作防呆規範（避免使用含禁用詞的複合詞，如「忽略」）。
3. **前端控制台防呆進化**：修復正則誤抓 `F:` 的問題，並針對禁用詞導入負向斷言（如排除「忽略」），同時新增「強制發布」按鈕，保留人類最高權限。
4. **腳本編號提示**：`setup-structure.yml` 生成 SP 包時，自動讀取 HANDOFF 的 `W:` 並印在頂部，防止 AI 忘記推算編號。
